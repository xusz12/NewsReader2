# 个人助手与文章问答

点击顶栏最右侧的「个人助手」或按 `Control+Q`，从右边缘展开长期主对话。再次点击或按同一快捷键即可收起。桌面可在对话展开时换文章、划词和追问。在左侧按 `Esc` 关闭设置、收起文章问答或返回单栏列表时，右侧助手保持展开。手机上助手占满顶栏以下的空间，关闭后继续从原位置阅读。「设置 → 阅读偏好与维护 → 阅读快捷键」可修改开合快捷键。

提问后，回复气泡显示「正在整理资料…」。输入框上方会提示整理上下文、搜索网页、抓取来源、查阅新闻库与记忆或撰写回复。完成时气泡一次显示全文。停止或失败的气泡显示「本轮没有生成回复」。

在底部等回复时，对话会跟随新回复滚到底部。向上翻阅时保留阅读位置，消息区右下角的小箭头可以回到底部。抽屉收起后有新回复完成时，顶栏入口会亮起红点。回到底部看到最新回复后，提醒自动清除。

首次使用可直接提问，名字留空时面板和模型均使用「个人助手」。从左侧导航进入「设置 → 研读与助手 → 个人助手」可随时修改名字、职责、runtime、模型和推理强度。首次安装采用当时文章问答的模型作为初始值，两处设置此后分别保存。

阅读器右栏的「文章问答」用于单篇新闻或报告。快捷键和划词「引用问本文」进入本篇会话。生成时气泡显示「正在整理资料…」，标题栏提示分析、检索、读取来源或撰写等阶段。成功结束后，全文一次填入原气泡。停止、失败或服务重启中断时，气泡显示「本轮没有生成回复」，可在原问题下重试。

文章问答通过现有 SSE 连接传递阶段和最终结果，断线后按任务查询同样的更新。两个 worker 可分别处理不同文章，临时历史默认保留 72 小时，也可设为 24 小时。本篇所有问答结束后可将完成的回复「提炼到想法」。个人助手有自己的任务锁，两篇新闻都在生成时仍可开始个人讨论。

## 从阅读器递入引文

新闻正文、译文、精读结论和要点可以递给个人助手，报告使用同一划词入口。点击时，输入框上方出现一张引文卡，已有草稿继续保留。再次递入会替换卡片，点「移除引文」可单独移除材料。桌面聚焦输入框，手机等待用户点击输入。生成期间可以准备下一条草稿和引文。

点击发送时，NR 将本轮问题和引文分别保存。快照包含条目 ID、当时的标题、链接、选中文字、来源类型及可用段落号。新闻通过条目 ID 定位，报告的阅读条目使用 `report:<报告 ID>`。关闭面板、原文更新或删除、右栏会话到期后，个人讨论里仍可阅读当时的引文。草稿和未确认请求号保存在当前标签页的会话存储中，网络重发沿用原请求号。

## 身份与存储

默认持久目录为应用设置文件旁的 `personal-assistant/`，可由 `NEWS_READER_PERSONAL_ASSISTANT_DIR` 指定。产品使用一个永久新闻库，个人助手独立保存自己的数据库和工作区。

```text
personal-assistant/
  assistant.sqlite3        # 身份 ID、名字、职责、模型配置、讨论、消息、任务状态
  workspace/
    MEMORY.md              # 简短长期记忆索引
    notes/*.md             # 偏好、事件判断及变化的专题笔记
  runtime/<thread>/<epoch>/ # 可重建的运行时会话，不作为记忆权威来源
```

升级在助手库中增加 `assistant_main_thread` 和 `message_quotes` 两张附表。前者最多一行，首次升级选取最近一次用户发言所在的讨论，相同时间按消息 ID 决定。已有讨论、消息、记忆沿用原 ID 和内容。空库在首次有效发送时，用同一 SQLite 事务建立主对话、任务、用户消息、引文及待生成回复。旧版 `threads.library` 列保留以兼容回退。

助手库中的 `assistant_reply_notice` 记录最新一条待看的已完成回复。升级前的历史回复沿用原状态，新的提醒与回复在同一事务中保存。

主线首次载入最新 30 条消息，向上每次最多再载入 30 条。用户发言和助手回复各算一条。「返回主对话」结束从旧通知打开的历史阅读，其他旧讨论可用 `discussion_search` 检索。每次新发言使用提交时的运行配置。重试仅对最后一轮失败或已停止的回复开放，沿用原模型、原问题、原引文和消息 ID。

新会话和会话重建使用当前记忆索引与最近最多 24,000 字符的已完成讨论，历史引文和序列化开销都计入预算。原生续聊只追加本轮问题与引文，记忆版本变化时才附上索引和笔记目录。更换 runtime、模型、推理强度或手动修正记忆后，助手在同一时间线上从数据库恢复上下文。未完成回复不参与历史重放。

运行时的正文片段只在内存中累积。阶段变化时更新任务进度，成功结束时在同一事务中写入完整回复、任务终态和待看提醒。失败、停止或重启中断的轮次保留问题和引文，助手正文为空。

运行时同时报告可靠的窗口用量与手动压缩能力时，NR 按完成轮的实际用量判断。达到 80% 会在原生缓存目录标记，下轮输入前显示「正在整理上下文」并等待原生整理完成。正常作答共用 300 秒预算，整理另有最多 45 秒。压缩失败或会话映射损坏时，同一请求最多重新建立一次原生会话。停止涵盖整理、重建和生成阶段。重启发现中断轮次时清理相应缓存。

身份和内容保存在本机；模型推理使用所选服务，查询结果和记忆会随需要传给它。应用不新增模型密钥存储方式。

个人助手在业务状态和上下文上独立：单独的配置、数据库、任务锁、讨论、记忆及原生会话目录。它与现有功能共用 Flask 服务、机器资源、模型运行时及模型账号；不是进程与资源完全隔离的另一应用。同一账号的限流与机器负载可能同时影响这些功能。NR 主库通过只读工具共享，现有任务入口、排队及清理规则不交给个人助手。

## 记忆机制与 Raft 参考

参考公开 Raft 源码提交 `db5e399f017d584e49597e3a28757645d6807893` 的组织方式：

- [创建 Agent 身份](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/server/src/services/agentService.ts)：身份与执行 Runtime 分开。
- [初始化 workspace](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/daemon/src/workspaces.ts)：持久 `MEMORY.md` 与 `notes/`，初始化不覆盖旧记忆。
- [系统指令](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/daemon/src/drivers/systemPrompt.ts)与[记忆使用指南](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/shared/src/raftCliGuide.ts)：先读简短索引，按需读取专题，学到值得保留的信息后主动整理。

这里只参考架构，没有复制 Raft 的实现。新建或重建原生会话时，NR 发送当前 `MEMORY.md` 全文和专题笔记文件名，笔记正文按需读取。续聊时，NR 对比这条讨论上次成功接收的记忆版本。索引或笔记正文有修改、笔记增删或改名时，下一轮重新附上索引和最新文件名，并提醒助手读取笔记的当前版本。记忆内容相同的续聊省去这段输入。主对话沿用所选旧讨论的版本记录。已有原生会话缺少记忆版本记录时，首次续聊会补送当前索引和目录。

助手将自述或确认的熟悉程度、解释偏好写入对应专题。跨多篇报道反复出现的思考习惯写成带日期的观察，并附多条用户发言出处。单次提问和作者引文保存在可搜索的历史中。用户明确表达的判断、猜想及修正保留「依据 → 推断 → 预判」、成立条件、反例、不确定性和来源。当前模型在作答前使用记忆工具整理这些内容，普通查询没有新的个人表达时无需写入。

`memory_write` 要求真实用户消息 ID，服务端核验作者并追加出处。文章内容、助手分析、Agent 归档不等于用户观点；收藏也不等于赞同。索引限 16 KB，单篇笔记限 64 KB，最多 200 个文件。更新采用内容哈希检查与原子替换，冲突时须重新读取。工具进程绑定当前任务；停止或重启中断后，旧进程不能继续通过工具写记忆。停止请求与记忆的原子替换使用同一文件锁：已开始的单次写入先结束，停止返回后不得再有该任务的记忆写入落盘。

设置支持查看、修改、删除笔记。删除笔记会移除索引中引用该路径的行；清空索引只重置 `MEMORY.md`，其他笔记保留。界面明确提示原始讨论仍保留，不承诺删除底层 runtime 自己保存的历史。用户修正优先于旧对话，指令禁止从历史自动重建已删除记忆。

## 查询与运行

`personal_assistant_tools.py` 是只使用 Python 标准库的 stdio MCP 服务，不导入 Flask 应用，不迁移数据库。

| 工具 | 作用 |
| --- | --- |
| `nr_schema` | 查看当前主库表结构和关联说明 |
| `nr_query` | 参数化只读 SQL，可跨所有业务表筛选、关键词搜索、关联、聚合及分页 |
| `discussion_search` | 检索个人助手消息，覆盖用户正文、引文原话及来源标题，支持讨论、消息 ID、字符偏移与分页 |
| `memory_list` / `memory_read` | 查看索引及按需读取笔记 |
| `memory_write` | 整理有用户表达出处的记忆 |

新闻、原文、翻译、重要、收藏、想法、事件、总结和报告均以 NR 主库为数据源，不复制业务表。查询连接使用 SQLite `mode=ro`、`query_only` 和 authorizer，拒绝写操作、ATTACH、PRAGMA 及扩展加载。单次执行限 2 秒、最多 100 行；长字段和大结果明确标为截断，可用 `LIMIT/OFFSET` 或 `substr` 继续读取。没有把全部新闻预载到提示词中。

Pi、DSH 与 Codex 经 OAR 的 `personal_assistant` 任务运行。每轮重新注册当前讨论对应的 `nr_assistant` 工具，写记忆前按 job ID 确认任务仍在运行。Pi 和 DSH 另有 `nr_web`，可检索最新公开资料并打开来源；Codex 使用其原生搜索策略。网页搜索根据本轮问题使用。

Pi 旧 CLI 会话映射在首次成功续聊后改为 OAR，并移除旧路由标记；原生会话 ID 不变。Codex 继续恢复同一原生 ID。接收完整完成结果后仍须等待进程正常结束，再保存成功状态；缺失结果、后续非法事件、非零退出、超时与停止均不能记为完成。中断后删除本模块运行缓存，下轮按已保存的完成消息重建，不重放失败草稿。

## 代码与接口

- `personal_assistant.py`：Flask Blueprint、持久化、每轮状态、停止及重启恢复。
- `personal_assistant_runtime.py`：隔离工作目录、统一 OAR 调用、原生续聊、流式事件、超时与子进程回收。
- `personal_assistant_tools.py`：全库只读查询、讨论检索、文件记忆与 MCP 协议。
- `static/personal-assistant.js` 和 `static/personal-assistant-settings.js` 管理右侧抽屉、主线历史、引文草稿和独立设置。

接口使用前缀 `/api/personal-assistant`。顶栏读取 `GET /threads/main`，经 `POST /threads/main/messages` 发送问题或原轮重试。历史通知读取 `GET /threads/<id>?message=<回复 ID>`，向上翻页使用 `before`，停止使用 `POST /threads/<id>/stop`。发送携带 UUID `request_id` 及可选的 `quote` 对象。设置与记忆继续使用 `profile`、`model-options` 和 `memory` 接口，分别通过 `epoch` 和 `revision` 检测并发修改。

抽屉在前台生成回复时，约每 1.1 秒读取一次 `GET /threads/<id>?status_only=1`。响应只含讨论、最新任务与待看提醒。发现任务结束后，通过同一接口的 `after` 参数取回刚完成的消息。该游标包含指定 ID，支持原位更新占位气泡和重试消息。回到前台或重新打开已有主线时，运行中的任务先查状态，已成功同步的对话只取最新消息 ID 之后的记录。增量范围超过 30 条时，服务端返回 `reset: true` 和最新 30 条，可继续向上翻页。

## 备份与回退

正式切换前等待在途回复和记忆编辑结束，备份 `assistant.sqlite3` 与整个 `workspace/`。SQLite 在运行时使用 WAL，应使用 SQLite 在线备份或停服务并完成检查点。记忆文件与数据库须取自同一静止时间段。原生缓存位于 `runtime/`，可从讨论记录重建。

回退演练使用已经写入引文的**升级后副本**。用 v0.6.14 打开该副本，沿用旧讨论记录的新闻库路径，检查原有消息、续聊、另建讨论、读取旧记忆。旧版显示用户问题与助手回复，引文仍存于 `message_quotes`。升级前的备份独立保留。

v0.6.16 分别用 v0.6.13 和 v0.6.15 生成的 SQLite 备份验证了升级。已完成消息和记忆可继续读取，运行中断的草稿会清空，已有引文和消息 ID 保留。两份副本都验证了新回复提醒、增量读取，以及写入新引文后回退至 v0.6.14 续聊和另建讨论。

## v0.6.15 本机验收（2026-11-27）

基线为 v0.6.14（`b3de611`）。Pi 1.6.0、DSH 0.2.2-rc.5、Codex 0.169.0 通过 OAR 0.134.0 连接本机隔离的模型与搜索端点。使用测试文章核对模型收到的内容。后端全量 2,177 项、OAR 桥接 62 项、Chromium 界面回归 166 项通过，另有 5 项 WebKit 触屏回归通过。

| 验收项 | 实测结果 |
| --- | --- |
| 并发与归档 | 两篇文章各占一个 worker 时，个人助手启动并调用搜索。三路都在运行时，第三篇已完成的新闻成功提炼到想法。另一次 DSH 单次归档耗时 92.91 秒，返回了有效结果。 |
| 模型设置与定期报告 | Pi 设置拒绝了模型不支持的推理强度。Pi 报告在原生默认设为 `low` 时发送了 `low`，显式选择 `off` 时关闭了推理。三个 runtime 使用隔离配置发起了报告请求，并修复了 Codex 报告启动与预检选择不同可执行文件的问题。 |
