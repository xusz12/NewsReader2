# 定期报告

阅读导航的「日报」包含日报、周报、月报三个列表；早报、午报、晚报属于日报。报告由独立的 `periodic_reports.py` 与 `static/report-panel.js` 管理，不读取旧日报文件，不使用积压总结或主题追踪的生成逻辑。

## 排期和启用边界

所有排期及取材边界使用北京时间 `Asia/Shanghai`，不依赖电脑当前时区。报告时间是开始整理的时间；完成速度取决于索引和模型。

| 期别 | 开始生成 | 新闻时间范围，左闭右开 |
| --- | --- | --- |
| 早报 | 交易日08:30 | 前日21:30—当日08:30 |
| 午报 | 交易日14:30 | 当日08:30—14:30 |
| 晚报 | 每日21:30 | 前日21:30—当日21:30，重新汇总完整24小时 |
| 周报 | 周一08:30 | 上周一00:00—本周一00:00 |
| 月报 | 次月1日08:30 | 上月1日00:00—本月1日00:00 |

首次启动新版时，在当前新闻库中永久记录 `activated_at`。不创建此前已经到期的报告，首期范围起点取“正常范围起点与启用时间的较晚者”。首周、首月可能不足完整周期，页眉如实显示实际取材范围。重启不重置启用时间；服务关闭期间只补齐启用之后漏掉的晚报、周报和月报。启动前错过的早报、午报不创建；已排队或已中断且租约失效的旧早午报标为「已跳过」，已完成的早午报保留。不生成启用前的材料或导入测试样稿。

独立调度线程按最近的排期设置等待，并以最长30秒的检查间隔处理时钟变化、唤醒和换库；生成线程串行领取队列，不阻塞调度。唯一 `edition_key` 防止重复期次。「到达排期」指当前时间已经跨过某一期的固定时刻，每跨过一个时刻创建一次任务；不是每30秒生成一份，也不是每日或每月统一建一批任务。长报告仍会占用唯一生成工作线程，后续期次会准时排队，未必能立即开始生成。

进程启动及调度中断超过90秒后恢复，都会先处理漏期，跳过旧早午报；正常运行期间在时刻之后几秒检查到仍照常创建。应用需要运行才能整理报告；无独立系统唤醒任务。相同时间优先处理早午晚报，其次周报、月报。

## 手动生成与删除

「日报」位于研究导航下，与主题追踪、新闻总结一样，激活时隐藏来源筛选。中栏右上角加号「新增日报」在按钮旁打开浮层，通过共享日历和月份网格选择；右栏继续保留原报告与阅读位置。手机也在列表上完成设置，提交后才进入报告详情。早报、午报、晚报只选择日期，分别对应前一天21:30至当日08:30、当日08:30至14:30、前一天21:30至当日21:30。周报选择起始日期，覆盖该日及后续6天（起始日00:00至第8天00:00），不限定从周一开始。月报只选择月份，覆盖完整自然月。新增「自定义」，只在此类型显示开始和结束时间，聚焦对应输入后以共享日历和小时／分钟 Picker 编辑，或直接输入 YYYY-MM-DD HH:mm；自定义报告归入日报列表。默认填入最近完整时段，页面预览实际北京时间范围。范围须已结束，取材包含开始时刻、不包含结束时刻。手动生成不受自动启用边界或交易日限制。

点击「开始生成」立即入队，沿用刷新索引、快照取材、模型、选稿、校验和重试流程。手动报告标注「手动生成」，按覆盖周期归档，不推进自动排期游标，不覆盖现有报告，不修改新闻标记或阅读状态。重复提交同一请求只创建一份；修改类型或时间、取消后重新打开表单时使用新请求标识；临时收起保留草稿和请求标识。

右栏顶部「删除」支持自动、手动、旧试生成和导入的报告。确认后仅删除报告和中间结果，原始新闻保留。正在生成时按钮禁用，服务端也拒绝删除；等待中和失败的任务可删除。保留已删除期次的轻量标识，避免重启补期或重放提交把报告重新创建。主动再次生成相同范围需使用新的请求标识。

## 归档与阅读

日报（含早午晚、自定义）与周报按月份分组，月报按年份分组，首次默认展开北京时间当月／当年；本次使用期间手动展开或折叠不会被轮询覆盖。早午晚报按窗口结束日，周报、月报与自定义按开始日归档，跨月周报仍归入起始月份，次年生成的12月月报归入上年。历史补生成不会被放到创建时间所在月份。

分组计数覆盖全量存档，展开后按组分页读取，每页30份；列表按覆盖日期倒序，同一范围按创建时间及ID倒序。新建或从定时任务记录打开报告时，展开对应归档分组。正文使用报头、导读、首要主题和其他主题的视觉层级，来源默认折叠，阅读字号与全应用一致。

## 生成进度

顶栏圆形状态器与新闻分类、主题追踪共用，日报分组包含早午晚报、周报、月报与自定义报告。任何页面均可展开查看等待、运行阶段、失败原因与重试时间，点击任务进入对应报告。顶栏每2秒读取活动任务元数据，空闲每30秒探测，隐藏页面暂停；创建、重试及删除后立即更新，完成后从状态卡移除。多个任务不合并成虚构的整体百分比。

任务在数据库中记录真实阶段及本次开始时间：刷新索引、读取新闻、准备材料、编写报告、校验、修正和保存。超出模型容量才显示分批筛选／归并的已完成批数与总批数；实际完成后更新计数。列表显示当前阶段，右栏展示阶段步骤、取材条数与本次耗时，设置中的执行记录同步展示。模型调用期间不编造百分比或预计完成时间。前台每3秒读取运行中报告，重新进入仍可看到已保存的进度；失败保留失败前阶段与重试时间。

## 取材、生成和保存

1. 领取报告后，先主动执行一次增量索引刷新。刷新至取材结束全程与手动刷新共享 `INDEX_REFRESH_LOCK`，避免手动重建索引打断取材；调用模型前释放锁。新闻目录不可用或索引异常时停止，不调用模型、不保存半份报告。
2. 刷新成功后在读事务中获取该范围的全部新闻标题和已有摘要，包含已读、未读、未标记和隐藏信源。以新闻发布时间选择，不能用入库时间过滤掉刚刚刷新发现的报道。不主动抓取正文；已取得且在截止时间前获取的正文可补充，最多12000字符并明确标为节选，标题与摘要不静默截断。
3. 保存不可变输入、当期规则和模型配置。`reports/selection-rules.json` 固化已获用户认可的真实数据库分析规则，不分析开发数据库的行为，不把未标记或已读当作偏好。新闻文本始终是资料，不是可执行指令。
4. 脚本读取所选模型的实际上下文容量并估算输入token。材料在预算内时，一次LLM调用完成选材、聚簇、成文；只有超出预算才保留新闻条目完整性分批选材，合并后的候选也只有超出同一预算才继续归并。没有32000／65000字符分界。所有输入引用必须被记为入选或舍弃；连续舍弃编号可用范围表达，脚本再展开校验。长周期直接从完整周期新闻比较累积变化、转折、落差和结果，不压缩已有日报。
5. 输出采用三条以内导读、重点主题、次重点简讯及折叠来源。取消固定的主题数和全文字符上限，早午晚报以5—10分钟阅读为编辑目标；重要事实、限定条件与反证优先保留。阅读时长根据实际内容估计，不能保证每份都严格落在目标范围。校验仍检查JSON结构、有效来源、引用覆盖和异常字段长度；不截断模型正文。
6. 保存可解析的草稿与已验证步骤。遇到某一主题、简讯或导读格式／来源错误时，只让模型返回指定字段的替换值，脚本拒绝改写其余字段；自动重试复用草稿及成功步骤。无法解析的JSON无法局部修复。无效装饰性加粗可由脚本直接清除。完整结果一次保存，已完成报告不可自动覆盖。校验能确认格式和引用有效性，不等同于事实与选稿质量的自动认证。

容量来自Codex解析后的本机配置（含profile）及模型目录，或Pi模型注册表。不会把所有模型都假定为1M。输入预算扣除最多32768 token的输出空间、模型有效上下文比例和10%的安全余量；`tiktoken`的本地估计不是各provider精确用量，无法使用时退回更保守的UTF-8字节估计。无法确定模型容量会明确失败，提示检查模型目录／本机模型配置。安装依赖使用 `python3 -m pip install -r requirements.txt`；首次使用分词器可能需要下载其编码数据，失败后本进程使用保守估计。

使用设置中「模型与 Agent → 功能：日报」独立选择的 Runtime 与模型，统一用于早午晚报、周报、月报及自定义报告，不再随 Chat 选择变化。Pi通过已安装SDK作无工具的单次模型调用，使用现有认证与models.json；不加载Agent扩展。Codex使用临时只读会话，关闭搜索、命令、外部MCP、应用及插件工具；不创建用户研究会话。需要这些扩展才可用的自定义Pi模型会明确失败，不擅自换模型。

一般失败按60／300秒自动重试，最多3次；界面保留失败状态和手动重试。20分钟租约防止重复领取，模型每轮最多15分钟，步骤完成时续租；进程中断后可恢复。重试复用已成功刷新的不可变输入，避免不同尝试混用材料。显式重试读取当前模型配置：相同配置保留成功步骤与可修复草稿，配置变化才清除派生缓存，不改变原取材时间或新闻状态。新版步骤使用独立版本键，避免读取旧流程的中间结果。

索引错误区分目录／文件不存在、路径不是目录、读取权限不足、数据库占用、磁盘空间不足、文件格式／编码错误和其他数据库错误；未知异常保留通用索引失败提示。原始异常文本不返回浏览器。报告列表和详情持续显示错误原因，自动重试期间显示已尝试次数及下次时间；进入报告列表或收到新的错误状态时使用共享 toast 提示一次，不在每轮刷新重复通知。此通知在报告页面内生效，不发送系统推送。

报告没有已读、已展示、阅读进度或补课状态。生成和打开报告均不写 `item_state`、`reading_checkpoints` 或主题的 `seen` 状态。

## 数据与接口

新增表由 `ensure_db()` 幂等创建，不改写旧新闻数据：

- `periodic_report_meta`：当前库令牌、首次启用时间和已检查的排期边界。
- `periodic_reports`：期次、状态、租约、材料快照、配置与完整结果。
- `periodic_report_steps`：与该期快照绑定的中间结果。
- `periodic_report_deletions`：已删除期次的标识与删除时间，避免自动补期或提交重放恢复删除项。
- `periodic_reports.progress_json / started_at`：真实执行阶段、分批计数、取材条数及本次开始时间；启动时幂等迁移旧库。

`GET /api/reports?kind=daily|weekly|monthly&offset=0&limit=30` 返回列表、完整分组计数、服务器北京时间、下期时间和启用时间；可传 `group=current` 或月份 `YYYY-MM`（日报／周报）、年份 `YYYY`（月报）分页获取单组，省略时仍返回全列表；`GET /api/reports/<id>` 返回完整正文；`POST /api/reports/<id>/retry` 携带 `database_token` 重试失败期次。

`GET /api/reports/manual-options` 返回五类固定报告和自定义的默认窗口、日期／月份选择值、当前北京时间和数据库令牌。`POST /api/reports/manual` 接收 `kind`、UUID `request_id`、`database_token`；固定报告使用 `selection`（YYYY-MM-DD，月报为YYYY-MM），服务端计算窗口并验证已结束；自定义使用 `kind=custom`、`period_start`、`period_end`。旧起止时间请求继续兼容。自定义只参与手动生成，自动排期仍为五类。手动报告使用 `manual:` 期次键，API返回 `is_manual`。

`DELETE /api/reports/<id>` 接收数据库令牌，事务内验证运行状态、写入删除标识、删除报告与步骤。旧 `preview-options / previews / <id>/preview` 接口保留兼容旧前端；旧试生成仍使用 `trial:` 与 `is_preview`，新入口不再创建试生成。旧 `/api/daily-briefings` 仅保留兼容，不为新入口供稿。

数据库备份应保留以上三表。源码回退不需要删除新增表；重新升级会延用原启用边界。

## 设置中的定时任务观察

「设置 → 定时任务」只读展示排期服务、生成服务、最近成功检查、启用时间、队列数量、当前阶段及五类报告的下次排期。最近20条执行记录包括自动生成、手动生成、旧试生成与导入样稿，错误和重试时间可见，点击可打开报告。各排期的「最近一期」只统计正式自动任务，样稿、手动生成与旧试生成不会改变该记录。

`GET /api/reports/schedule-status` 只读取任务元数据，不读取正文、模型配置和中间输出，不刷新新闻、不调用模型、不启动服务或推进排期。调度线程记录最近成功检查；超过90秒未成功更新、线程停止和排期异常分别显示。交易日历异常、状态接口不可用会提供可操作提示。此页面可见时每10秒刷新，离开、手机返回分类或切入后台后停止；请求失败时明确显示上次结果及时间，不伪造空队列。

## 交易日历维护

`reports/trading-calendar.json` 当前含2026年度[上交所公布的休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20251222_10802510.shtml)。周六日始终休市，调休工作日不会被当成交易日。新年度安排公布后按同结构增加年度，随应用更新发布；也可用 `NEWS_READER_TRADING_CALENDAR_PATH` 指向维护方的同格式JSON文件。

缺失某年度日历时不猜测交易日：该年度早午报暂缓，晚报、周报、月报继续。列表API返回 `calendar_warning`，日报列表显示提示。这项日历需逐年维护；索引刷新只同步本地采集文件，不能保证上游采集本身没有遗漏。

## 验证

`tests/test_periodic_reports.py` 使用隔离库验证启用边界、交易日、窗口、刷新与并发取材、调度独立于模型、唤醒补期、租约与重试；`tests/test_report_observation.py` 验证观察只读、排期与健康状态、错误、元数据隔离和历史上限；`tests/ui/schedule-settings.spec.js` 验证状态刷新、草稿保护、停止轮询及主题／手机布局；`tests/test_report_manual.py` 验证自定义时间、进度、提交幂等、删除隔离与防止重建；`tests/test_report_previews.py` 验证旧试生成兼容入口、完整窗口、提交幂等、排期隔离、删除范围及新闻状态保护；`tests/test_report_generation.py` 验证一次成文、容量分批、取消旧压缩门槛、引用覆盖及局部修复；`tests/test_report_model.py` 验证容量解析、模型协议完成、超时清理、工具限制，并通过本地模拟模型服务检查真实Pi SDK调用与截断拒绝；`tests/ui/reports.spec.js` 使用合成报告验证真实API与页面交互、手动生成与删除、运行进度、研究导航、简讯与旧报告兼容。合成样稿只出现在测试服务器，不写入实际新闻库。
