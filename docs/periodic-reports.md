# 定期报告

阅读导航的「日报」包含日报、周报、月报三个列表；早报、午报、晚报属于日报。报告由独立的 `periodic_reports.py` 与 `static/report-panel.js` 管理，不读取旧日报文件，不使用积压总结或主题追踪的生成逻辑。

## 排期和启用边界

所有排期及取材边界使用北京时间 `Asia/Shanghai`，不依赖电脑当前时区。报告时间是开始整理的时间；完成速度取决于索引和模型。

| 期别 | 默认开始生成 | 默认新闻时间范围，左闭右开 |
| --- | --- | --- |
| 早报 | 交易日08:30 | 前日21:30—当日08:30 |
| 午报 | 交易日14:30 | 当日08:30—14:30 |
| 晚报 | 每日21:30 | 前日21:30—当日21:30，重新汇总完整24小时 |
| 周报 | 周一08:30 | 上周一00:00—本周一00:00 |
| 月报 | 次月1日08:30 | 上月1日00:00—本月1日00:00 |

日报标题中的日期表示刊期，不表示只收录该自然日的新闻；实际取材以报告保存的起止时间为准。例如晚报窗口设为前日21:00至当日21:00时，11月4日晚报会包含11月3日21:28和22:17的报道，恰好在11月4日21:00发布的新闻属于下一期。修改窗口只影响后续任务，历史报告保留原范围。

「设置 → 日报任务」的报告排期默认显示文本，点击「编辑」后可分别设置五类报告的开始生成时间与新闻窗口。小时、分钟使用共享 Picker；早午晚报的新闻起点可选前日或当日，终点为当日。周报保持上周一至本周一、月报保持上月1日至本月1日的周期，可各自调整起止时刻。五类窗口独立，不自动联动其他报告或启动排期；默认值见上表。

早报的启动须早于午报、午报须早于晚报。每类启动时间不得早于自身新闻窗口结束；同日窗口必须起点早于终点，前后端共同校验。保存立即唤醒调度；修改启动时刻后，新时刻若已过去，从下个周期开始，当天已经到期的期次不因延后重复生成。窗口变更只影响生效之后到期的任务，不立即创建补报。

启动配置与历史保存在 `report_schedule`、`report_schedule_history`，窗口独立保存在 `report_windows`、`report_window_history`。早午晚窗口为 `{start_day:-1|0,start:"HH:MM",end:"HH:MM"}`，周月窗口为 `{start:"HH:MM",end:"HH:MM"}`。`report_schedule.news_window()` 统一计算范围；自动任务按该期历史启动时刻选择当时生效的窗口，普通停机补报沿用历史值。改时跳过某一期不会拉长下一期；已创建报告、材料快照及重试始终保留原起止时间。设置以原子替换保存，旧客户端省略窗口字段时保留现有配置。

旧版本保存过早的启动时刻时，读取不重写配置和历史；任务至少等到窗口结束才启动，设置行显示需修正的时间。后续修改排期或窗口须满足上述截止限制，其他功能的设置保存不受旧值影响。缺少窗口配置的旧安装使用上表默认值，不修改设置文件。

首次启动新版时，在当前新闻库中永久记录 `activated_at`。不创建此前已经到期的报告，首期范围起点取“正常范围起点与启用时间的较晚者”。首周、首月可能不足完整周期，页眉如实显示实际取材范围。重启不重置启用时间；服务关闭期间只补齐启用之后漏掉的晚报、周报和月报。启动前错过的早报、午报不创建；已排队或已中断且租约失效的旧早午报标为「已跳过」，已完成的早午报保留。不生成启用前的材料或导入测试样稿。

独立调度线程按最近的排期设置等待，并以最长30秒的检查间隔处理时钟变化、唤醒和换库；生成池最多并行3份报告，超出上限的等待领取，不阻塞调度。SQLite写事务内同时检查并发上限与领取租约，防止多线程重复执行同一份报告。唯一 `edition_key` 防止重复期次。「到达排期」指当前时间已经跨过某一期的固定时刻，每跨过一个时刻创建一次任务；不是每30秒生成一份，也不是每日或每月统一建一批任务。

进程启动及调度中断超过90秒后恢复，都会先处理漏期，跳过旧早午报；正常运行期间在时刻之后几秒检查到仍照常创建。应用需要运行才能整理报告；无独立系统唤醒任务。相同时间优先处理早午晚报，其次周报、月报。

## 主动暂停与恢复

「设置 → 日报任务 → 报告排期」提供红色暂停／绿色开始图标按钮，分别带有「暂停定时／恢复定时」的可访问名称，点击立即生效，不需要保存设置。统一控制早报、午报、晚报、周报、月报的自动入队；手动生成、已创建的等待／运行／重试任务、材料快照清理照常。暂停状态保存在当前新闻库，关闭应用、重启和编辑排期时间都不会自动恢复。

每次暂停记录起止时间，恢复时排除这段时间内（包含暂停与恢复时刻）到期的所有报告，不补生成，也不把下一份日报拉长为多日窗口。普通停机在暂停区间以外错过的晚报、周报、月报仍按原规则补齐。暂停时不推进报告游标，避免丢掉暂停前已有的停机缺期；恢复后的游标扫描跳过已保存的暂停区间。重复发送相同的暂停／恢复状态不会延长或重写区间。自动入队与暂停写入使用同一 SQLite 写锁，暂停提交后不再插入新自动任务；已经创建的任务不会取消。

`POST /api/reports/schedule-pause` 接收布尔 `paused` 和当前 `database_token`，返回实际 `schedule_control`；不解析模型配置、不要求交易日历正常，也不调用模型。观察和列表接口返回同一暂停状态，暂停时五类报告的下一次排期为空，界面显示「已暂停」，快照清理仍显示下次时间；恢复后重新计算未来排期。按钮请求期间禁用，失败显示原因并重新读取状态，轮询和操作都保留未保存的时间草稿。

## 材料快照清理

首次启用清理功能后7天执行第一次，此后每7天一次。排期和最近清理结果保存在当前新闻库的 `periodic_report_snapshot_cleanup`，重启不重置。应用关闭时不执行，恢复后补一次清理，下次为本次成功清理后7天，不连跑历史清理期次。该维护任务不依赖交易日历和模型，也不占用模型并发名额。

清理保存满7天的共享材料，以及已完成／已跳过报告中的旧独立材料快照；同时间窗口存在等待、运行或失败可重试的报告时保留材料，即使该报告还未绑定快照。清理在非阻塞索引锁及 SQLite 写事务下执行，与并行取材隔离；报告正文、最终来源、模型配置和取材时间保持不变。生成步骤缓存仍保留原有生命周期。报告的已清理共享材料引用设为空；超过保留期后再新建同窗口报告，会重新刷新索引取材，不承诺仍能和旧报告使用同一材料。

每周检查一次，因此闲置材料通常保留7至14天；仍被任务占用时延后。清理失败整次回滚，在排期中显示错误，5分钟后自动重试；无法写库时记录服务日志，下次检查继续尝试。SQLite 释放的页供后续写入复用，不在应用运行中执行阻塞式 VACUUM。只读观察接口不触发清理。

设置页面底部显示快照材料的实际 UTF-8 数据大小（KiB／MiB），包括共享材料和旧独立材料；共享快照只计一次，不按引用报告数重复累加。该数值不包含最终报告、其他新闻数据或数据库空闲页。使用中的材料大小单独显示。观察接口通过 SQLite 长度聚合，不将材料正文载入 Python 或返回前端。

「清除报告材料快照」经共享确认框执行，不受7天保留期限限制，清除全部闲置材料；未完成任务占用材料的保护规则与自动清理一致。操作使用索引锁和写事务，索引正在刷新时返回稍后再试；失败回滚且保留原大小。清理结果更新页内大小，已有报告和来源保留，后续同窗口报告重新取材。手动操作不改写每7天自动清理的排期或上次自动执行记录。

`POST /api/reports/snapshots/clear` 接收当前 `database_token`，返回 `removed_count`、`freed_bytes` 与更新后的 `snapshot_storage`。观察接口同步返回快照总字节数、可清理字节数、受保护字节数和材料份数；清理不启动生成任务。

## 手动生成与删除

「日报」位于研究导航下，与主题追踪、新闻总结一样，激活时隐藏来源筛选。中栏右上角加号「新增日报」在按钮旁打开浮层，通过共享日历和月份网格选择；右栏继续保留原报告与阅读位置。手机也在列表上完成设置，提交后才进入报告详情。早报、午报、晚报只选择日期，按表单打开时保存的时刻预览取材范围；默认分别对应前一天21:30至当日08:30、当日08:30至14:30、前一天21:30至当日21:30。周报选择起始日期，覆盖该日及后续6天（起始日00:00至第8天00:00），不限定从周一开始。月报只选择月份，覆盖完整自然月。只保留这五类报告，移除「自定义」时间范围入口；已生成的历史自定义报告仍可阅读。早午晚报日期默认选中北京时间当日；时段尚未结束时仍保留当天选择，显示提示并阻止提交。周报、月报默认最近完整周期；页面预览实际北京时间范围。浮层不再显示右上角关闭按钮，保留底部取消及 Escape／外部点击关闭。报告类型上方显示所属模型组已保存的 Runtime 和模型；临时关闭后重新打开、或从后台返回时刷新模型信息，日期草稿保留，读取失败可重试。范围须已结束，取材包含开始时刻、不包含结束时刻。手动生成不受自动启用边界或交易日限制。

点击「开始生成」立即绑定当前报告类型的 Runtime、模型及推理强度等选项并入队；自动排期与旧试生成入口也在创建时绑定。随后修改设置只影响以后创建的报告。模型容量在执行时解析，不在创建请求中运行模型。手动报告标注「手动生成」，按覆盖周期归档，不推进自动排期游标，不覆盖现有报告，不修改新闻标记或阅读状态。重复提交同一请求只创建一份，并保留第一次绑定的配置；修改类型或时间、取消后重新打开表单时使用新请求标识；临时收起保留草稿和请求标识。

同一新闻库、相同北京时间起止范围的报告共用一份不可变新闻快照及当时的选稿规则，不因Runtime、模型或报告类型不同而重新取材；不同类型仍保留各自的编辑要求。月报另保存一份同窗口共享的不可变补充材料，用于固定重要标记、补入首次月报取材时已入库但原快照缺少的当月重要新闻，以及提供历史重要新闻背景候选；日报和周报不使用这份补充材料。同窗口第一份先刷新索引并建立快照，其他任务等待或直接复用，随后各模型独立并行生成，各自保存输出、进度与中间结果。新建对比报告不会纳入该窗口后来补入或修改的新闻。窗口内全部报告都删除后清理共享快照，再次创建才重新取材。

保留期内，旧报告已有的独立快照不被改写；首次新增同窗口对比报告时优先采用按创建时间、ID排序的第一份旧快照。旧库中已有多份不同材料的报告保留原样，不追溯强行统一；比较时以相同的 `snapshot_id` 确认同一材料。更新前尚未绑定配置的任务在首次执行或手动重试时绑定一次。

右栏顶部「删除」支持自动、手动、旧试生成和导入的报告。确认后仅删除报告和中间结果，原始新闻保留。正在生成时按钮禁用，服务端也拒绝删除；等待中和失败的任务可删除。保留已删除期次的轻量标识，避免重启补期或重放提交把报告重新创建。主动再次生成相同范围需使用新的请求标识。

## 归档与阅读

日报（含早午晚及历史自定义报告）与周报按月份分组，月报按年份分组，首次默认展开北京时间当月／当年；本次使用期间手动展开或折叠不会被轮询覆盖。早午晚报按窗口结束日，周报、月报与自定义按开始日归档，跨月周报仍归入起始月份，次年生成的12月月报归入上年。历史补生成不会被放到创建时间所在月份。

分组计数覆盖全量存档，展开后按组分页读取，每页30份；列表按覆盖日期倒序，同一范围按创建时间及ID倒序。新建或从顶栏任务进度打开报告时，展开对应归档分组。卡片、正文、顶栏任务和日报任务运行状态标出该报告绑定的Runtime与模型，正文在 Runtime／模型旁依次显示生成用时、取材条数、收录条数及快照取材时间，使用现有元信息排版，日报、周报、月报共用。取材条数记录实际送入生成流程的新闻材料数（已排除视频来源）；收录条数按正文与简讯引用的来源去重，同一来源重复引用只计一次，不计未采用材料。月报取材条数包含补充评审的历史背景候选，收录条数包含实际引用的历史背景；未采用的背景不计收录。两项数量不因原新闻删除或材料快照清理而减少。旧报告优先从已有生成计数或可靠的保留快照回填取材数，无法恢复的显示「取材 未记录」，不填成0；真实空报告显示0条。生成用时保存于 `generation_seconds`，累计所有尝试从领取任务至成功或失败的实际耗时，包含等待取材、索引、模型与校验，不包含任务排队及失败后的重试等待。自动及手动重试均保留累计值；运行中在累计值上叠加本次耗时，失败及等待重试时冻结显示。每次执行用单调时钟计量，避免系统时间调整干扰；租约心跳将本次耗时写入 `attempt_seconds`，服务意外中断后只累计最后一次心跳确认的执行时间，不把停机时间算入。中断前尚未持久化的尾段无法精确恢复。旧的已完成报告仅在有有效开始／结束时间时迁移回填，未知不编造；后续更新时间不再改变用时。正文使用报头、首要主题和其他主题的视觉层级，来源默认折叠，阅读字号与全应用一致。

中栏卡片右侧显示实际开始执行时间（`started_at`，北京时间），重试显示最近一次开始时间；尚未开始的排队报告显示「等待执行」，没有可靠记录的旧报告显示「未记录执行时间」。归档与排序继续按新闻覆盖周期。列表不再显示导读摘要。

已完成报告的右栏工具栏提供「复制全文」，复制标题、期别、含年份的新闻时间范围、模型与生成元信息、全部主题正文、简讯、去重后的来源标题／时间／链接与「本期完」；折叠来源也包含在内。复用共享剪贴板及失败提示，不改变来源展开或阅读位置。

## 生成进度

顶栏圆形状态器与新闻分类、主题追踪共用，日报分组包含早午晚报、周报、月报与自定义报告。任何页面均可展开查看等待、运行阶段、失败原因与重试时间，点击任务进入对应报告。顶栏每2秒读取活动任务元数据，空闲每30秒探测，隐藏页面暂停；创建、重试及删除后立即更新，完成后从状态卡移除。多个任务不合并成虚构的整体百分比。

任务在数据库中记录真实阶段及本次开始时间：刷新索引、读取新闻、准备材料、整理全期新闻、统筹主题与跨日进展、编写章节、校验、修正和保存。长报告按已保存的整理批次、章节更新完成数量；委派事件显示协作状态。列表显示当前阶段，右栏展示阶段步骤、取材条数与累计耗时，设置中的执行记录同步展示。模型调用期间不编造百分比或预计完成时间。前台每3秒读取运行中报告，重新进入仍可看到已保存的进度；失败保留失败前阶段与重试时间。

## 取材、生成和保存

1. 领取报告后，先寻找同时间范围的共享快照；已有快照时复用，否则主动执行一次增量索引刷新。刷新至取材、原子发布快照全程与手动刷新共享 `INDEX_REFRESH_LOCK`，锁内二次检查避免竞争任务重复取材，唯一窗口约束防止跨实例发布不同材料；调用模型前释放锁。新闻目录不可用或索引异常时不发布快照，不调用模型、不保存半份报告。
2. 刷新成功后在读事务中获取该范围的全部新闻标题和已有摘要，包含已读、未读、未标记和隐藏信源，但排除 Bloomberg 视频页。入库与取材复用 `feed_sources.is_bloomberg_video_url()`，按 Bloomberg 主域／子域及 `/news/videos/` 路径判断；标题或普通文章 URL 包含“视频／video”不作为排除依据。取材端同时覆盖尚未重新索引的历史视频记录。以新闻发布时间选择，不能用入库时间过滤掉刚刚刷新发现的报道。不主动抓取正文；已取得且在截止时间前获取的正文可在入选后补充写作，最多12000字符并明确标为节选，标题与摘要不静默截断。快照保存完整取材不代表选稿时会把摘要或正文交给模型。
3. 不可变新闻输入及当期规则保存在共享表中，每份报告记录快照引用；模型配置已在任务创建时单独固定。`reports/selection-rules.json` 固化已获用户认可的真实数据库分析规则，不分析开发数据库的行为，不把未标记或已读当作偏好。新闻文本始终是资料，不是可执行指令。
4. 选稿统一只提供标题、来源、发布时间和引用编号，不提供摘要、正文、正文可用性或长度；去重、分批与选稿路径也只依据这些标题资料。小报告先形成标题初稿并固定入选编号，有可用摘要或正文时再单独调用模型完善写作，没有补充材料则直接保留标题支持的表述。写作只接收入选来源，并校验不能新增或漏掉入选编号；正文纠正标题时写清纠正或不确定性。Ultra 始终保留原生报告工具与委派能力；其他报告的标题提示超过 `min(24000, 输入预算/2)` 时进入 `report_workspace.py` 工作区。Codex标题工作批次目标24000 token，Pi根据容量设为24000—96000 token，均不超过输入预算的一半。小报告入选正文超过单次容量时，将已确认的标题初稿转为固定章节计划，使用工作区分页写作，不重新选稿或静默截断。URL和内部ID由快照保留，不参与选稿。
5. 输出只保留重点主题、次重点简讯及折叠来源，不生成简介或导读；旧报告的导读在读取时忽略，原存档不重写。取消固定的主题数和全文字符上限，早午晚报以5—10分钟阅读为编辑目标；重要事实、限定条件与反证优先保留。阅读时长根据实际内容估计，不能保证每份都严格落在目标范围。校验仍检查JSON结构、有效来源、引用覆盖和异常字段长度；不截断模型正文。
6. 工作区分别记录标题处理覆盖、候选事件、章节计划与最终引用。每批来源必须进入事件或显式舍弃；确认计划前可重新审视被舍弃标题。`report_sources` 的检索只查标题，`report_source` 的分页也只返回标题资料，不泄漏摘要、正文或其可用性。`report_plan` 确认全部候选取舍后固定入选名单和章节，此时仅入选新闻开放摘要与正文；后续不能更改选稿或引入未入选来源。每章须引用本章所有入选编号，遗漏只补写到简讯并保留主体；无正文的新闻仍保留。主编辑须通过 `report_draft` 回读每章最新正文，修订撤销旧回读确认，`report_finish` 拒绝未回读版本。最终由程序按计划拼装已验证章节，不再把全文压缩为单次摘要。覆盖与引用校验不等同于事实与选稿质量的自动认证。
7. 只因“已引用”与 omitted 范围重叠时，本地从 omitted 移除已引用编号，不改变事实、不再调用模型。缺失编号单独补审，允许补入事件/简讯，禁止默认当作舍弃。其他格式错误仅修复指定字段及相关材料；每次修复后重新校验，格式修复暴露出的遗漏继续单独补审，最多三轮。已应用的局部修复也会保存；修复预算不足有独立错误，不再错误地称为整期资料过大。可解析原稿、已验证步骤与工作区持久保存，重试使用同一快照、模型与流程版本。完整结果一次保存，已完成报告不可自动覆盖。

2026-11-03视频排除规则也适用于旧快照：生成入口在内存中剔除视频来源，保留其余来源原编号，不重写原始独立／共享快照或已完成报告。有视频被剔除时，生成步骤与工作区缓存使用 `exclude-videos-v1:` 前缀，避免复用含视频事实的旧答案、校验结果或草稿；重试仍能复用过滤后的新缓存。同窗口新建报告和旧任务重试均遵循此规则，全部材料为视频时生成空报告且不调用模型。跨此次升级比较旧成稿与新报告时，相同 `snapshot_id` 代表相同原始材料，实际送入模型的来源可能因视频排除而不同。

2026-11-03标题选稿流程使用 `title-first-v1:` 生成步骤前缀及 `v4-title-first-1` 工作区版本，避免重试复用曾看过全文的旧选稿结果。已完成报告和不可变快照不重写；未完成任务、新建报告及同窗口对比报告采用新流程，包括早午晚报、周月报及历史自定义报告。新流程中断后继续复用已完成的标题选稿、入选写作与章节审核。v0.4.12起，各处折叠报道来源通过共享 `reader-sources.js` 按发布时间从旧到新展示，引用编号与存档不变。

### 月报的重要新闻与历史背景（2026-11-12）

- 月报在既有选稿偏好与编写要求上增加必收保障：取材窗口内发布、补充快照建立时仍标为重要的新闻，全部进入原有主题正文或简讯。延续发布时间左闭右开、北京时间及 Bloomberg 视频排除规则，不按标记发生月份筛选。未标记新闻仍按原有标准选稿，不作负向判断。
- 同一事件的当月进展、转折、纠正及相反证据按原标准筛选并合并进原有主题；不能仅因属于同一公司或行业而强行关联。历史重要新闻仅作为可选背景候选，按标题资料判断关联；不单独组成当月主题或简讯，不要求全部纳入。引用背景的每个段落或简讯必须同时引用关联的当月新闻，并明确历史时间或背景身份。
- 标题阶段仅增加 `monthly_role=important/background` 这一标记及时间范围信息，不开放摘要、正文或正文可用性。候选事件中的 `important_refs / background_refs` 保留同样的约束，跨批归并与计划不能丢失。确定名单后，仅入选来源开放摘要与正文；原有归属、日期、限定条件和反证要求继续适用。
- 直接成文、容量分批、Pi 工作区和 Codex 原生工具共用校验：初筛和归并禁止舍弃必收来源，章节计划禁止遗漏重要新闻或建立纯历史章节，正文校验拒绝漏引重要新闻及独立历史段落。失败继续沿用原有局部修复与重试，不保存不完整成稿。
- `report_monthly.py` 定义月报角色与补充规则。`periodic_report_snapshots.monthly_snapshot_json` 首次由月报在写事务及租约校验下建立；同窗口月报的重试、重启及不同模型对比复用同一份补充快照。之后新增新闻或改变重要标记不会改变这组材料，材料清理后再生成才重新取材。旧独立快照使用该报告自己的 `periodic_reports.monthly_snapshot_json`，保留其原始材料不变。
- 补充快照与原快照一起计入存储用量并沿用清理保护和7天保留规则。只增加可空字段，幂等升级；已完成报告不重写。月报步骤使用 `title-first-v1:monthly-important-v1:` 前缀，工作区身份同样加入 `monthly-important-v1`，防止未完成旧任务复用不含必收保障的选稿结果；其他报告类型流程版本不变。

容量来自Codex解析后的本机配置（含profile）及模型目录，或Pi模型注册表。Codex优先使用解析后的 `model_context_window`；否则读取 `model_catalog_json` 指定的目录，支持自定义provider／profile。仅在未指定目录且使用默认OpenAI provider时读取 `models_cache.json`；指定目录缺失、无效或不含所选模型时不回退到无关缓存。不会把所有模型都假定为1M。输入预算扣除输出空间、模型有效上下文比例和10%的安全余量。Codex预留最多32768 token；Pi推理模型预留最多65536 token（思考与JSON输出共用 `maxTokens`），关闭推理时预留32768，均不超过注册表输出上限或上下文的1/4。已有Pi任务的旧容量元数据在执行前升级，不修改其模型和推理档位。

Pi明确返回 `length` 时报告输出截断及实际用量，禁止保存部分JSON；长报告仅对该请求扩大一次输出预算，最多131072 token且仍受模型/上下文限制，相应扣减输入预算。不能扩大或仍截断则明确失败，不自动降低推理、切换模型或反复提交相同请求。实测 Flash/max 一次32K请求的25773 token用于推理，只剩约6K供正文，因此旧的统一32K限制不能当成纯正文额度。`tiktoken`的本地估计不是各provider精确用量，无法使用时退回更保守的UTF-8字节估计。无法确定模型容量会明确失败。安装依赖使用 `python3 -m pip install -r requirements.txt`；首次使用分词器可能需要下载编码数据，失败后本进程使用保守估计。

设置中「模型与 Agent」仅提供两组报告模型：「日报（早／午／晚）」共用 `feature_models.reports`，「周报／月报」共用 `feature_models.reports_periodic`；两组分别选择 Runtime、模型和推理程度，不提供自定义报告模型设置。升级时周月报组从原日报配置复制，保存后两组互不联动。自动及手动创建均按类型绑定，已有报告及其重试不受默认值修改影响。某组未配置模型时，其任务明确报错，不阻塞另一组的自动排期。Pi 使用现有 SDK 认证和 models.json，由程序最多并行整理3批；候选目录在适度预算内完整交给主编辑，否则分页读取。计划确定后，程序用同一模型最多并行写作3章，写作请求同时提供事件记录和所引用原始新闻；超过单次预算的章节由主编辑通过工具分页读取后继续写作。主编辑始终能通过 JSON 工具循环检索全量快照、修订计划/草稿并最终复核，不加载 Agent 扩展或暗中换用小模型。Codex 的长报告和 Ultra 使用原生委派，最多3个并行子 Agent，与主编辑共享仅限本报告的 MCP 工作区；仍关闭网页搜索、shell、用户其他 MCP、应用、插件、记忆、goals 和 hooks。私有 Unix socket 目录权限0700，MCP桥接不提供文件、数据库或网络访问工具。非Ultra的普通短报告仍是无工具的单次成文。

Codex 保留临时只读会话及 Fast 强制关闭。当前 CLI 临时会话的 `fork_turns="all"` 会因缺失持久父会话记录失败；因此提示要求使用 `fork_turns="none"`，在委派任务中明确编辑规则、批次/章节及保存要求，子 Agent 从共享工作区重新读取资料，不依赖父对话或改变新闻数据。子任务结束消息不能完成报告；只有工作区完整验证通过且主会话正常完成才保存成功结果。模型目录中的原生委派选择由 CLI 处理，不将 Ultra 伪装为 Max。

一般失败按60／300秒自动重试，最多3次；确定的输入/修复/工作区容量错误、已用完扩容机会的输出截断和容量未知直接显示失败，避免相同请求反复自动消耗。界面保留手动重试。20分钟租约与60秒心跳防止重复领取；普通模型调用最多15分钟，每次长报告尝试最多60分钟，Codex连续15分钟无协议或工作区工具活动则超时。主会话正常结束但工作区尚未完成时，会开启新的短上下文继续剩余工作；连续两轮没有有效进展才报未完成，不能把进度汇报当成最终报告。Pi只保持最多3个整理请求在途，某批失败后停止排入后续批次并清理未完成请求，已保存成果可恢复。结束、超时或服务停止会清理本次进程组和临时工具桥接。工作区 journal 写入 `periodic_report_steps`，以快照、模型、批次划分与流程版本的哈希隔离，每次更新检查原任务租约，子任务并发写入串行持久化；重试恢复已整理批次和章节。换模型对比需创建另一份报告。

长报告结果的 `generation` 保存流程版本、处理覆盖、候选数、最终引用数、已回读章节及编辑复核说明；调用记录保存耗时、本地估算输入、运行时返回的 token 用量、请求的推理程度及可观察到的协作事件。CLI 用量按其返回口径记录，不能据此断言已包含全部子 Agent 用量；未返回的信息不推算。记录不包含凭据、原始错误或提示词。比较委派效果时应固定快照、模型及主模型实际推理档位，并分别检查耗时与事件/时间线/反证质量，不能只用字数或一次测试断言提升倍数。

索引错误区分目录／文件不存在、路径不是目录、读取权限不足、数据库占用、磁盘空间不足、文件格式／编码错误和其他数据库错误；未知异常保留通用索引失败提示。原始异常文本不返回浏览器。报告列表和详情持续显示错误原因，自动重试期间显示已尝试次数及下次时间；进入报告列表或收到新的错误状态时使用共享 toast 提示一次，不在每轮刷新重复通知。此通知在报告页面内生效，不发送系统推送。

报告没有已读、已展示、阅读进度或补课状态。生成和打开报告均不写 `item_state`、`reading_checkpoints` 或主题的 `seen` 状态。

Pi 报告桥接在锁定版本的 SDK 中仅加载 `core/model-runtime.js`，避免完整包入口附带的 CLI 与交互界面初始化影响目录查询和生成；SDK 升级时须验证模块路径及实际本地模拟服务测试。Node或SDK不可用时单独报告运行依赖错误，提示安装Node.js 24+并执行 `npm ci --ignore-scripts`，不再显示为模型容量未知；模型目录、生成及手动重试均保留这一错误分类。

## 数据与接口

新增表由 `ensure_db()` 幂等创建，不改写旧新闻数据：

- `periodic_report_meta`：当前库令牌、首次启用时间和已检查的排期边界。
- `periodic_reports`：期次、状态、租约、固定配置与完整结果；`snapshot_id` 指向共享快照，旧 `snapshot_json` 保留兼容。
- `periodic_report_snapshots`：按起止时间唯一的新闻材料与选稿规则；包含取材时间，与具体模型输出分离。
- `periodic_report_snapshots.monthly_snapshot_json / periodic_reports.monthly_snapshot_json`：分别为共享窗口和旧独立快照保存月报补充材料，含固定的重要 ID、补充来源、历史背景及建立时间；非月报不消费。
- `periodic_report_schedule_pauses`：主动暂停起止区间；最多一个未恢复区间，与排期游标共同保证恢复不补生成。
- `periodic_report_snapshot_cleanup`：固定7天清理的下次排期、上次结果和失败重试，不创建报告期次。
- `periodic_reports.source_count`：生成前持久保存的取材条数，完成或材料清理后保留；`selected_source_count` 根据存档正文与简讯的实际引用计算并在列表／详情返回。
- `periodic_reports.generation_seconds`：已结束尝试的累计耗时，成功或失败均结算，重试保留；未知为空。
- `periodic_reports.attempt_seconds`：当前尝试由心跳保存的耗时，成功、失败或租约失效时并入累计值并清零；不向前端单独展示。
- `periodic_reports.model_label / snapshot_captured_at`：运行时／模型显示名称与取材时间，供轻量观察接口直接读取；不返回配置正文。
- `periodic_report_steps`：与该期快照绑定的中间结果。
- `periodic_report_deletions`：已删除期次的标识与删除时间，避免自动补期或提交重放恢复删除项。
- `periodic_reports.progress_json / started_at`：真实执行阶段、分批计数、取材条数及本次开始时间；启动时幂等迁移旧库。

`GET /api/reports?kind=daily|weekly|monthly&offset=0&limit=30` 返回列表、完整分组计数、服务器北京时间、下期时间和启用时间；可传 `group=current` 或月份 `YYYY-MM`（日报／周报）、年份 `YYYY`（月报）分页获取单组，省略时仍返回全列表；`GET /api/reports/<id>` 返回完整正文；`POST /api/reports/<id>/retry` 携带 `database_token` 重试失败期次。

`GET /api/reports/manual-options` 返回五类日期报告的默认窗口、日期／月份选择值、当前北京时间、`windows`、按五类返回、映射到两组配置的 `model_defaults`（含 `model_label` 与不含凭据的 `model_settings`）和数据库令牌；顶层同名模型字段继续表示日报组配置，供旧客户端兼容。`schedule_times`、`window_times` 仅为旧客户端保留。日窗口默认选择当前北京时间日期；模型信息来自对应报告类型配置，不运行模型或查询容量。`POST /api/reports/manual` 接收 `kind`、UUID `request_id`、`database_token`；日期报告提交 `selection`（YYYY-MM-DD，月报为YYYY-MM）及表单打开时绑定的单类 `window`。服务端校验完整字段与窗口有效性，计算范围并验证已结束。打开表单期间修改启动排期或窗口设置均不改变该表单所见范围；重新打开后使用新窗口，包括手动生成历史日期。周月边界不是00:00时，表单显示精确起止时间。旧表单不带 `window` 且当前规则已变化，或提交的旧 `schedule_times` 与默认窗口不符时，返回 `report_window_changed` 要求刷新。新建请求仅接受五类日期报告，`kind=custom` 返回 `report_window_invalid`；五类报告的旧起止时间请求仍兼容。历史自定义报告的阅读、删除和重试保留；手动报告使用 `manual:` 期次键，API返回 `is_manual`。

新增日报的「临时模型设置」默认收起，未更改时使用当前报告类型已保存的配置。展开后通过三个 Picker 选择 Runtime、模型、推理程度，可恢复当前类型默认模型；切换类型保留已选临时模型，未选临时模型则立即使用新类型默认值；临时关闭保留草稿，取消或创建成功后清空。`POST /api/reports/model-options` 接收 `kind` 与 `runtime`，按报告类型和 Runtime 返回公开模型目录和可用推理程度：Codex 复用该类型 Profile／服务商的本地缓存目录，缺失时读取 CLI；Pi 使用本机 SDK 注册表。仅展开时读取目录，不运行推理，也不修改全局配置。

Pi 直接调用模型时传入由报告 ID 派生的 `sessionId`，同一报告的选材、成文、修复及重试共用，不同报告隔离。SDK 据此附加 OpenCode 所需的 `x-opencode-session` 请求头，避免 Go 返回缺少会话标识的 HTTP 400；独立传输调用没有报告 ID 时生成临时 UUID。此标识仅用于请求路由，不创建 Chat 会话，不改变已保存的模型配置。

创建请求可附带 `model_override`（`runtime`、`model`、`reasoning_effort`，Pi 另含 `provider`）。服务端只允许这些字段，校验推理能力，继承 Codex 的已保存 Profile／服务商和只读沙箱限制，创建时写入该报告的不可变配置；Pi 的推理程度实际传入 `completeSimple`，`off` 使用关闭推理的 SDK 语义。Codex 执行统一固定 `service_tier="default"` 并关闭 `features.fast_mode`，不继承本机 Fast；已创建报告及重试同样适用，推理程度不变。目录校验在 SQLite 写事务外完成。同一 UUID 的重放直接保留原绑定，不重新查询模型能力；五类日期报告均支持覆盖，快照共享规则不变。

`DELETE /api/reports/<id>` 接收数据库令牌，事务内验证运行状态、写入删除标识、删除报告与步骤。旧 `preview-options / previews / <id>/preview` 接口保留兼容旧前端；旧试生成仍使用 `trial:` 与 `is_preview`，新入口不再创建试生成。旧 `/api/daily-briefings` 仅保留兼容，不为新入口供稿。

数据库备份应保留以上全部报告表，包括暂停历史和维护排期。源码回退不需要删除新增表；重新升级会延用原启用边界。

## 设置中的日报任务观察

「设置 → 日报任务」展示排期服务、生成服务及并行上限、最近成功检查、启用时间、队列数量、所有运行中报告的模型和阶段，以及五类报告和材料快照清理的下次排期。报告排期按下次执行时间从近到远排列，交易日历不足而无下次时间的任务放到最后；默认文本显示，点击「编辑」后出现小时／分钟 Picker，沿用设置保存、撤销和草稿流程，保存成功后返回文本模式，取消编辑还原启动时间和新闻窗口草稿；轮询不重建控件或关闭菜单。保存后立即更新实际排期，每行独立显示新闻窗口；编辑时分别显示开始生成、新闻起点与新闻终点，不自动改动另一组配置。不再展示「最近执行」区块；已有报告仍在日报／周报／月报列表中查看。观察接口保留最近20条轻量元数据供旧客户端兼容。各排期的「最近一期」只统计正式自动任务，样稿、手动生成与试生成不会改变该记录。

`GET /api/reports/schedule-status` 只读取排期设置和任务元数据，不解析报告的正文、绑定模型配置和中间输出，不刷新新闻、不调用模型、不启动服务或推进排期。调度线程记录最近成功检查；超过90秒未成功更新、线程停止和排期异常分别显示。交易日历异常、状态接口不可用会提供可操作提示。此页面可见时每10秒刷新，离开、手机返回分类或切入后台后停止；请求失败时明确显示上次结果及时间，不伪造空队列。

## 交易日历维护

`trading_calendar.py` 为新闻采集和定期报告提供同一份日历。应用启动时开启独立后台更新线程，平时每周检查[上交所休市公告](https://www.sse.com.cn/disclosure/dealinstruc/closed/list/)，获取当年与已公布的下一年度完整休市安排。12 月尚未取得下一年时改为每天，取得后恢复每周；跨年立即重新检查。缺少当年日历时立即检查，失败后每小时重试；已有当年日历时，网络／解析失败保留本地日历，沿用当前检查周期。进入12月会缩短此前的每周等待，不因重启重置等待。更新不依赖模型或 opencli，不占用数据库写锁；读新闻、状态查询和排期只读取本地文件。

`reports/trading-calendar.json` 保留2026年官方日历作为保底；运行缓存位于当前新闻数据库同目录的 `trading-calendar-cache.json`，保存年度数据、来源、最近检查／成功时间、失败代码和下次检查时间。只有七个法定节日均包含、日期有效的年度公告通过校验后，才原子替换缓存，失败保留上一次完整数据。重启／升级直接使用缓存，跨年无需常规手动维护。周六日始终休市，调休工作日不会被当成交易日；跨年元旦休市区间也覆盖上一年末的日期。

缺失某年度日历时不猜测交易日：该年度早午报及交易日加采暂缓，常规每日采集、晚报、周报、月报继续。列表API返回 `calendar_warning`，日报列表显示提示。日历恢复后补排当前服务连续运行期间漏掉的早午报；已有期次与删除记录、暂停区间、休眠和重启后的早午报不补期规则保持有效。自动维护仍依赖官方公告可访问且格式可识别，不能提前保证尚未公布的日期。

运维需要固定自定义日历时，可用 `NEWS_READER_TRADING_CALENDAR_PATH` 指向同格式JSON文件；设置后以该文件为唯一来源，关闭自动更新，不合并或覆盖维护方的数据。

## 报告研读与来源（v0.4.6）

报告正文提供高亮和引用提问，不提供添加想法或将 Agent 回复存为想法的入口；进入来源新闻后仍可使用新闻的想法功能。来源标题无下划线，重要／稍后再看与新闻流共用状态。

已完成报告的详情响应增加 `reader` 和 `source_items`。`reader` 包含正文、研读主体、高亮与 Agent 快照，保留旧版想法字段兼容历史数据；`source_items` 按来源 URL 映射当前新闻及其状态，不写回生成时的存档内容，失效来源保留原始信息。

右栏工具栏「已阅读」仅由用户主动点击触发。按正文与简讯的来源引用收集 `source_items`，按新闻 ID 去重，通过共享 `ItemStateQueue`／`ReadBatchWriter` 和 `/api/news/mark-read-by-ids` 将这些新闻设为已浏览；折叠来源同样覆盖，未收录的取材新闻与失效映射不受影响。保留首次浏览时间及全文阅读状态，成功同步全局计数。随后调用 `POST /api/reports/<report_id>/read`，携带 `database_token`；服务端在写事务中核验新闻库、报告已生成及当前可映射的引用新闻均已浏览，才写入独立的 `periodic_reports.read_completed_at`，重复请求保留首次完成时间，不改写生成正文、模型和生成时间。列表与详情均返回该字段，旧报告迁移时为空，不从来源的浏览状态推断报告已阅读。

两步保存成功后，按钮以共享完成样式显示勾及「已完成」，中栏卡片与右栏页眉均显示「已经阅读完」。完成记录按报告独立保存，来源相同的另一份报告仍需主动确认。全部来源已浏览或没有可映射新闻时仍可确认报告完成；未生成报告不显示操作。任一步失败均保留重试入口，不提前显示完成标签；迟到列表／详情响应不撤回成功记录，切换新闻库时清空前端完成缓存。打开、停留或复制报告不触发此操作。`tests/test_report_reading.py` 与 `tests/ui/report-mark-read.spec.js` 覆盖操作范围、简讯、重复来源、状态与计数、按报告持久化、旧库迁移、失败重试、库令牌校验及迟到响应。

研读主体为 `report:<报告ID>`，在现有 `/api/news/<item_id>/highlights`、`notes`、`agent/*` 和 `chat/archive` 接口中复用同一实现，不向 `items` 插入虚拟新闻。高亮和想法使用 `newsreader-report:<报告ID>` 存储键，Agent 继续按新闻库隔离。报告正文由主题标题、段落和简讯按双换行串联，沿用 Unicode 偏移与正文哈希校验；研读 Agent 取得报告正文和存档来源清单，默认使用 Chat 配置，独立于报告生成模型。删除报告同时清理其高亮、想法和临时会话，来源新闻及其状态保留。

共享 Agent 面板用发送按钮旁的纯图标按钮打开共享模型选择浮层，通过 `GET /api/news/<item_id>/agent/model-options` 读取目录，通过 `PATCH /api/news/<item_id>/agent/session/model` 选择当前会话的 Runtime、模型和推理程度。请求携带 `session_id` 与 `selection`；服务端在目录校验后重新检查会话与运行任务，运行中拒绝切换。显式选择持久保存在会话中，不受后续默认设置变化覆盖；切换保留消息和任务历史，清理旧原生会话映射，下一轮携带已有对话重新建立上下文。`agent_sessions.model_override` 为兼容新增字段，旧会话默认0。
