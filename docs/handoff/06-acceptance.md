## 资产移交

- [ ] 核对源码基线 `de1dec7fe15a536ef6fc802df02fbfafbf30566e` 和 v0.0.15；区分发布基线与后加交接文档。
- [ ] 授予新团队所需仓库读写、审查和版本发布权限；如果迁移仓库，明确新的更新源和分支策略。
- [ ] 确定主项目及品牌素材交付授权；保留第三方依赖和资源的许可文件。

- [ ] 接收方配置独立 Pi/Codex、翻译服务及必要的网络权限；密钥不通过源码或普通文档传递。

## 接手安排建议

第一天完成仓库访问、样例运行、架构走读和测试结果复现。随后完成真实数据副本恢复、采集与模型依赖接入、业务场景验收。首个迭代优先处理测试日期稳定性、localhost 代理策略及持续集成，再按新团队目标安排功能开发。

正式切换应在数据和运行验收完成后安排；不能只凭源码包可解压就切换。若外部账号或资产尚未移交，填写具体责任人、替代方案和预计完成日期，不留模糊的“后续处理”。
