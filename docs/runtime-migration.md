# Runtime 统一调用迁移清单

2026-11-16 的迁移分批覆盖 Pi、Codex。目标是统一 Agent 的启动、会话、事件、取消和清理；直接模型 API、分类等专用服务不为了形式统一而改成 Agent。

OAR 负责管理底层 runtime。底层仍需要 Pi RPC 进程和 Codex app-server；要撤掉的是 NR 自己维护的多套执行与事件解析分支。

## 外置 DSH 与 DeepSeek 联网工具（2026-11-20）

NewsReader 通过 OAR 0.128.1 调用本机 DSH。探测时优先使用 `OAR_DSH_BIN` 指定的可执行文件，其次使用 `PATH` 中可用的 `dsh`。macOS 还会在个人与系统「应用程序」目录查找官方 DeepSeek Harness 桌面版，并通过系统注册的应用标识 `com.deepseek.dsh` 查找移到其他位置的安装。OAR 直接调用应用包内的 `Contents/Resources/runtime/cli/bin/dsh`，设置页显示识别出的桌面版本和模型数量。另装 CLI 的方式是 `npm install -g @deepseek-ai/dsh`。[官方桌面版说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md)

设置中选择 DSH 后才探测安装并读取目录，成功的目录缓存两分钟，可手动刷新。各功能分别保存服务商、模型和推理档位。先读取 DSH 的 ACP 与全局模型配置；仅有旧桌面或 Web 配置时，优先读取桌面配置中的模型路由。[OAR DSH 适配器](https://github.com/botiverse/oar/blob/v0.128.1/docs/runtimes/dsh.md)

报告预检从 DSH 读取所选模型的上下文长度，优先采用该模型显式配置的输出上限。若服务商在 DSH 内置模型目录中，预检可按同一服务商和模型 ID 补全输出上限。只提供上下文长度时，报告最多预留 32,768 个输出 token，且不超过上下文的四分之一。缺少有效上下文长度时，预检会提示检查模型配置。

在「设置 → API 密钥与连接 → DeepSeek」配置密钥。工具进程按环境变量、系统钥匙串的顺序取用凭据。文章问答、个人助手和联网主题研究通过本地 stdio MCP 使用 `web_search` 和 `web_fetch`。模型仍通过自己选定的服务商推理，搜索与抓取由 DeepSeek 按成功请求分别计费。主题定义和初始化要求工具取得有效来源，工具调用记录和模型自己给出的链接都不能代替这项检查。[DeepSeek 网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)

Pi 与 DSH 在这些会话中直接暴露 NR 注册的工具。个人助手也可读取新闻库、讨论及记忆。Codex 沿用原生搜索。DSH 原生对话在 NR 的私有目录中续聊，每轮只发布已完成的会话数据；归档、材料总结、翻译、连接测试和报告使用临时目录。长报告仅开放报告工具。主题任务和文章提问重试都使用原任务的模型。手动更换文章会话模型后，重试旧问题会临时使用其原模型，下一轮新问题使用当前会话的选择。翻译后备使用所选 Pi 或 DSH 的文章问答配置，旧开关沿用，默认 Pi。

2026-11-20 在隔离新闻库用 Pi 和外置 DSH 0.2.2-rc.5 验收。两者都选用 OpenCode Go 的 `qwen3.8-flash`。在同一篇测试文章追问旧报道的后续与官方发布日期，两者均实际搜索并抓取来源，给出 Python 3.15.0 的 2026-10-09 发布日期及官网链接。第二轮确认版本号时均复用各自原生会话，直接根据上一轮回答。个人助手也分别通过 `discussion_search` 找到测试讨论，再引用外部官方来源作答。[Python 官方发行页](https://www.python.org/downloads/release/python-3150/)

## v0.5.10 第一批的调用与边界

- 当前新闻面板通过 `/api/news/<id>/agent/jobs` 创建后台任务，支持流式回答、停止与重试；旧 `/api/news/<id>/chat` 同步接口仍保留，但两者的 Pi、Codex 执行都经过 OAR。归档继续使用 `/chat/archive`。
- Pi 新闻请求明确标为 `task=news_chat`，使用 `createPiRuntime({execution:"subprocess"})`。OAR 管理 RPC、流式事件、原生会话和进程树，NR 不再选择或解析这批功能的 CLI JSON 路径。
- `scripts/pi_rpc_entry.mjs` 仅补充 Pi 启动策略：聊天保留原生 MCP 配置及 codemode／tool_search；归档加上无工具、无持久会话、无项目上下文等参数。它不实现另一套会话或事件循环。
- Pi 使用私有配置副本，包括模型与 MCP 凭据；全局资源、MCP 过滤与暴露方式仍由 Pi 原生加载。只加载已获 Pi 原规则信任的项目资源；未信任项目也可经 OAR 工作，但不加载其资源。不会自动授信或安装项目包。
- Pi 旧 CLI 映射可由 OAR 恢复同一原生 ID；成功后才提交 `runtime=oar` 并撤掉旧路由标记，失败不改映射。旧同步原生会话先复制到 NR 私有会话目录，原文件不改；更早的后台会话继续按既有机制一次性重放 NR 保存的可见历史。
- Codex 新闻请求由 OAR 管理 app-server，继续沿用旧原生 ID，固定只读沙箱、不请求审批、标准速度、实时搜索。成功后才提交 NR 映射；失败、空结果、取消或不完整终止不算成功。
- NR 的 Codex 自定义模型输入、服务商覆盖和 Profile 已停用，无对应 CLI 回退。保留目录模型、推理强度和本机默认。旧空字段兼容；已绑定非空覆盖的旧会话明确拒绝，不静默改换配置。
- 本批没有把个人助手的 NR 查询／记忆工具加给新闻聊天。第五批已完成剩余生成调用方迁移，并删除公共原生 CLI 执行与事件解析分支。

## 归档与一次性会话

归档使用完整对话材料、原会话绑定的模型与推理强度，在独立会话中生成。对话按 JSON 数组保留角色、引用和多行正文。Codex 通过 OAR 公开的 `outputSchema` 把结果限定为单个 `summary` 字符串，原生 Responses 请求携带严格 JSON Schema，`maxLength` 为 300 与原对话正文长度的较小值，由 OAR 原生传递此约束。桥接只提取 `summary`，空字符串映射为无内容结果，格式不符明确报错。Pi 继续生成纯文本。

首次无正文或返回「无实质内容」时，带完整原材料复核一次；首次超长时，带实际草稿、实测长度和保留计数余量的修改要求压缩一次，原材料用于核对。每次都是新会话，不恢复原聊天。两次仍无有效正文则明确失败；不截断、不编造、不放宽 300 字及原对话长度限制。后端始终独立检查最终长度，即使模型服务忽略 Schema 也不保存超长内容。验证通过才原子保存想法，失败保留原想法和原聊天。Codex 归档每次允许 300 秒，保留原会话推理强度；超时仍回收 OAR 和原生进程。

2026-11-16 修复 Codex 归档的结果解析：`promptAndWait.text` 会拼接过程说明和流式草稿，不能直接当作最终正文，否则可能误触发 300 字限制。现在从 OAR 保存的记录中选取本轮主 Agent 的 `item/completed` 最终答复，排除 commentary、草稿、子任务及其他轮次；没有有效最终答复就明确失败。该规则同时用于 Codex 新闻聊天的最终保存，流式预览照常显示。

同日继续复现了独立的生成失败：有实质事实的对话仍可能返回无内容标记或空答复，另有调用触及原 90 秒超时。页面此前在归档请求结束后无条件清掉状态，失败时只短暂弹出提示，再显示旧聊天的「本轮已完成」。现在归档状态按文章／会话保留，成功、失败与聊天完成分开显示；切换文章后的迟到响应只更新原文章，归档期间禁用同会话的发送和新建，保留未发草稿。

2026-11-16 长度约束修复的验证：217 项相关 Python 回归、52 项 OAR 桥接测试通过，包括 Schema 到达真实 Codex 的 Responses 请求、短对话动态上限、结构化结果提取、模型忽略长度约束／格式错误／空结果时保护原想法。此前 53 项界面回归覆盖桌面／手机、浅色／深色／系统明暗／墨水屏，以及状态保留、重试保存和跨文章并发归档。沿用原 `gpt-6.1-terra/max`，用两段真实对话和一段短对话执行完整归档 API，分别一次生成 300、291、12 字，耗时约 43、37、11 秒，均在隔离库新增一条 Agent 想法且原会话不变，未向用户新闻库写入测试想法。

耗时对照：迁移前使用 `codex exec --ephemeral`，同样读取完整对话、沿用原模型／推理强度，并在超长时再次生成。对同一段材料测量，旧 CLI 启动约 0.13 秒，总耗时 54.5 秒，输出 312 字；OAR 会话启动约 0.14 秒，使用 Schema 的整轮耗时 45.9 秒，输出 300 字。两次都使用相同模型及 `max` 推理强度，但输出约束不同且每条路径仅测一次，不能据此声称普遍性能差异；可确认本次主要等待发生在模型生成阶段。没有过去具体成功操作的耗时日志，无法还原当时更快的完整原因。

- **Pi：** OAR 管理 RPC；原生 `--no-session` 不落盘原生会话，`--no-tools` 与通配排除禁用工具，不读项目上下文或技能。临时配置和 NR 目录在结束或超时后清理。
- **Codex：** OAR 0.128.1 的临时会话沿用 NewsReader 的适配。`scripts/oar_codex_ephemeral.mjs` 对锁定版本的 OAR 加载代码做一个受检查的内存补丁，只向原生 `thread/start` 补充 `ephemeral:true`，不修改 node_modules，不另写原生 RPC 客户端。版本或代码接缝改变时明确报错，不退回 CLI，也不改用持久会话。归档关闭 web search，维持只读沙箱，并要求只整理给定材料；OAR 的 Codex 接口尚不能统一禁用所有内置工具，因此不把提示词约束描述成完整的工具隔离。

升级 OAR 时必须重新检查该补丁和原生归档用例；上游提供等价公开能力后删除补丁，改用公开选项。DSH 的后台任务可能越过主轮次，宿主跟踪任务 ID，在会话释放前停止仍在运行的任务。

## 第二批的调用与边界

本地回归：243 项相关 Python 测试、55 项 OAR 桥接测试、78 项总结／主题界面用例通过；包括真实 Pi 与本地 MCP 的成功搜索／额度错误模拟，失败调用计数为零。

新闻总结和主题追踪共享 `news_summaries.run_oar()`，统一使用 OAR JSONL 协议，撤掉该入口的 Codex CLI 命令与原生事件解析；Pi 不再选择 CLI 兼容路线。任务绑定的模型、推理强度、配置快照、900 秒时限、取消、失败与保存事务保持原有约定。

- 新闻总结与主题时间线精简使用 `task=material_summary`；Pi 无工具、无会话落盘，Codex 关闭搜索、只读沙箱及独立临时会话。宿主发现任何工具调用都会终止该材料任务，不写入结果。Codex 尚无通用内置工具禁用接口，因此不把其提示词与事件拦截称为完全工具隔离。
- 主题定义、定义讨论与初始历史研究使用 `task=web_research`，Pi 保留原生搜索扩展、MCP、项目原有信任规则及发现工具，但禁用本地读写和命令工具；Codex 使用原生实时搜索。只统计完成且未报错的搜索调用，搜索开始、工具发现及失败结果不能作为已联网的证据。定义和初始化仍必须有检索证据。
- 两种 Runtime 都使用新建临时会话，不读取或覆盖新闻聊天的映射；Pi 原生 `--no-session`、Codex 受版本检查的 ephemeral 适配保持无原生会话落盘。结束和取消清理整个自有进程树与私有配置。
- 预览按实际 JSON 请求估算输入大小，一次性任务不重复传递相同全文作为续聊提示词。原新闻引用、标读事务、主题修订校验、精简预览／应用／恢复逻辑保持不变。

2026-11-16 真实界面验收使用独立 SQLite 和设置副本，连接实际 Pi／Codex 及真实模型，未向用户数据写入测试记录。Codex 新闻总结、联网生成定义、历史时间线及精简预览成功；Pi 新闻总结、时间线精简预览／应用／恢复成功。搜索事件修正后，Codex 界面重试成功，诊断确认两次检索完成，Codex 精简无工具调用。Pi 的现有 Ollama 搜索返回额度不足，真实联网验收仍待外部搜索服务恢复或用户确认其他安排。此项不计作已通过。

## 第三批的调用与边界

个人助手统一经过 `personal_assistant_runtime.run()` → OAR bridge（`task=personal_assistant`）；Pi 使用 OAR RPC，Codex 使用 OAR app-server，无个人助手原生 CLI 回退。两者每轮通过 OAR `mcpServers` 显式注册 NR MCP，并绑定当前任务 ID，恢复会话也更新这项绑定。

- 原名字、身份、讨论数据库、记忆文件、workspace、模型选择、推理强度和凭据来源继续使用。切换 runtime 或手工修正记忆仍提高 epoch，后续按规范化的已完成历史重建上下文。
- Pi 只开放六个 NR 工具，不加载个人扩展、技能、提示词模板、项目上下文或用户 MCP。旧 CLI 映射保留原生 ID，成功后迁为 OAR 并清除旧路由。Codex 保留原生只读沙箱、never 审批、标准速度及项目文档禁用策略，不改变其原生工具／本机 MCP 范围。
- 查询保持 SQLite 只读约束；记忆继续校验路径、容量、revision 和真实用户消息出处。停止与原子记忆替换共用文件锁，停止返回后当前任务不能继续提交写入。
- 完成结果必须唯一且完整，宿主等待桥接进程正常结束后才保存成功；异常、超时、取消后清理自有进程树和私有配置，失败上下文不会用于下轮续聊。

2026-11-16 联合回归通过 283 项 Python 用例、56 项 OAR 桥接用例；个人助手 15 项界面用例覆盖桌面／手机、浅色／深色／系统／墨水屏及全局阅读字号。原生测试实际创建 Pi CLI 和 Codex CLI 旧会话，再由 OAR 恢复同一 ID、历史及 NR MCP；同时覆盖工具进程超时、停止回收和停止／记忆写入竞争。

真实 computer use 验收继续使用第二批的独立新闻库：Codex 查询 3 条新闻并写入带用户消息出处的记忆，续聊检索原讨论；切换 Pi 后读取同一笔记，查询新闻并合并新偏好；两种 runtime 均完成停止后再回复，切换后身份、历史和记忆保留。设置页面确认笔记含两轮用户出处，隔离库共 5 轮完成、2 轮停止，无遗留临时配置。修复实测发现的旧停止消息在下一轮重新显示生成中问题，并完成页面复测。

截图保存在本地忽略目录 `output/oar-validation/batch3-assistant-memory.png`。第 2 批的 Pi 公网搜索额度限制与个人助手 NR 工具验收分别记录；不以本批通过替代该联网验收。v0.5.11 没有独立提交；按最新指定版本，将第二、三批变更合并整理为 v0.5.12。该提交保留 Pi 公网搜索受现有 Ollama 额度限制的验收记录，不将此项计作通过。

## 后续批次的完成条件

每批同时检查 Pi、Codex：原来的模型与凭据、工具范围、历史、停止、重试、失败记录和最终结果均可用，才能撤掉该功能的旧分支。既有队列与已绑定配置也应覆盖。新的 Agent 功能沿用共享 OAR 入口，用任务配置表达差异。

普通 API 的结构化输出、概率、置信度、超时与后备顺序继续由原服务适配器负责；不要为迁移重新实现成聊天提示词。目录、容量和连接测试是配套能力，按第五批约定分别处理，不改变功能是否属于 Agent 的判断。

## 第四批的调用与边界

- 自动、手动、对比生成、修复、重试都使用 `report_model.run`，不存在报告专用的 Codex CLI 或 Pi 单次 SDK 生成分支。

- Pi 通过本地预算扩展设置服务商支持的输出上限，并检查原生结束原因和已报告输出用量；截断或超预算结果不能保存。对不支持上限的 ChatGPT／Codex 协议网关只做完成校验，不声称远端硬截断。长报告可扩大一次预算并从工作区继续，保留原模型及推理档位。
- Codex 保留只读、关闭 Fast／联网与外部工具，以及原生子 Agent；工具调用、子任务与根会话用量经 OAR 事件读取，不再解析 CLI JSON。
- 根会话完成、OAR 释放会话且桥接进程正常退出之后才接受结果；取消、迟到结果、重复完成事件和非零退出均不算成功。工作区仍受租约和停止检查保护。
- 模型目录／容量接口仍只读元数据；这类查询不交给 Agent。

## 第五批的调用与边界

- `runtime_tasks.run()` 统一正文／X 正文及采集字段的 Pi 翻译后备（`translation`）和 Pi/Codex 草稿连接测试（`connection_test`），经共享 OAR bridge 执行。后备顺序、所选模型、推理强度和翻译结果校验保持原有约定。
- 每次请求独立临时目录，不恢复或保存原生会话。Pi 禁用工具、MCP、扩展、技能、提示词模板和项目上下文；Codex 连接测试复用报告的隔离启动限制，关闭外部 MCP、搜索、子 Agent 等工具能力。Codex app-server 仍可能列出少量无外部服务的内置发现工具；宿主拒绝任何实际工具事件。
