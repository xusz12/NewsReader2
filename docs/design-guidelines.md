# 项目设计与协作规范

本文件纳入 Git 版本管理，适用于整个仓库，是开发者与 AI Agent 的统一设计入口。新增页面、组件和交互默认沿用本项目的设计语言；修改既有界面时，保留已经确认的产品约定。用户明确调整规范时，同步更新本文件及对应设计文档。

## 1. 规范入口与优先级

涉及界面的工作开始前，先阅读本文件和当前组件映射，再按改动范围查阅基础规范、品牌规范和相关实现。

| 文档 | 职责与使用方式 |
| --- | --- |
| [项目设计与协作规范](design-guidelines.md) | 固定设计原则、导航约定、基础尺度及开发检查要求 |
| [当前 Token 与组件映射](design-token-mapping.md) | 当前组件的实际样式、交互及后续修订；是组件实现的直接依据 |
| [修订设计规范](../DESIGN_SPEC_AND_TOKENS_Fix.md) | 色彩、字体、布局、圆角、阴影与基础 Token 的完整定义；重点查阅第 2–5、8 节 |
| [品牌资源规范](brand-assets.md) | 标志、字标、主题配色、图标资产与生成方式 |
| [变更记录](../CHANGELOG.md) | 查询已确认调整的版本和背景 |

发生冲突时，依次采用：**用户当前明确要求 → 本文件的固定约定 → 当前组件映射及对应变更记录 → 修订设计规范的基础规则**。用户要求改变固定约定时，应在同一改动中更新文档，避免留下相互矛盾的规则。

[旧设计文档](DESIGN_SPEC_AND_TOKENS.md)、[早期界面重构记录](ui-refactor.md) 与未纳入仓库的 `news-reader-workbench.html` 仅供历史对照。修订规范第 6–7 节也保留了部分原型规则；卡片选中、稍后看配色、Agent 归档、移动导航、设置分类等均以当前组件映射为准。现有代码与规范不一致时，先核对后续变更记录，不直接把偶然实现提升为新规范。

## 2. 统一设计语言

- 采用 **Financial & Research Editorial（报刊式新闻研读工作台）**：突出新闻、长文和研究内容，保持克制、紧凑、清晰的阅读层级。
- 浅色主题使用温暖纸张底色与陶土红强调色；深色使用冷蓝灰背景；墨水屏使用黑白实色。具体色值引用 Token，不另建页面专属配色。
- 通过衬线标题、系统正文、留白、细边框和有限强调建立层次。避免加入与现有界面无关的渐变、玻璃效果、厚重阴影或大面积装饰卡片。
- **Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.** 避免不必要的次级标签和说明，优先通过布局、分组与留白表达关系，仅保留有助于理解和操作的补充文案。
- 相同语义复用相同控件、字号、间距、圆角、状态色和交互。新增功能先寻找现有组件与样式，确有新角色时再扩展设计系统。
- 复用应落到实际结构与组件类，不只复制相近的 CSS 数值。新视图的工具栏、阅读容器、标题、列表和表单直接消费对应共享组件；页面专属样式只处理现有组件无法表达的结构。共享组件的后续调整应同时作用于所有使用它的页面。
- 界面文案延续现有中文术语；加载、空白、成功、失败、禁用等状态应清晰可辨，状态信息同时用文字或图标表达。

## 3. Token 与样式职责

| 文件 | 维护边界 |
| --- | --- |
| [static/tokens.css](../static/tokens.css) | 基础布局、字体、字号、主题色、圆角与阴影；与修订规范第 8.1 节保持一致 |
| [static/design-tokens.json](../static/design-tokens.json) | 与修订规范第 8.2 节保持一致的导出；仅覆盖该节列出的子集，完整派生色、阴影及墨水屏定义以 CSS 为准 |
| [static/style.css](../static/style.css) | 应用补充 Token、组件样式、状态和响应式适配 |
| [static/index.html](../static/index.html) | 页面结构、语义与可访问属性；先加载基础 Token，再加载应用样式 |

- 颜色使用 `--bg`、`--surface`、`--surface-subtle`、`--surface-raised`、`--fg`、`--muted`、`--border`、`--border-strong`、`--accent` 等语义变量。背景与前景成对选择，覆盖默认、悬停、选中、禁用和焦点状态。
- 字号使用 `--fs-*`，间距优先复用 `--space-*`（2、4、8、12、16、20、24、32、48px），圆角使用现有角色变量。新增固定值应有明确用途，并记录到组件映射。
- 不在组件中重新定义基础布局、字号、圆角和阴影 Token。修改基础值时同步修订规范与对应导出；组件特有规则放在组件层，应用补充变量放在 `style.css` 的相应主题层。
- 编辑现有规则，避免靠文件末尾反复叠加覆盖、无作用域选择器或 `!important` 修补局部问题。

## 4. 布局与移动端固定约定

| 项目 | 规范 |
| --- | --- |
| 顶栏 | 桌面52px，≤920px为50px（`--header-height`，响应式规则由 `tokens.css` 提供） |
| 桌面 ≥1280px | 三栏；导航 248px，列表 430px／最小 360px，右侧阅读区自适应 |
| 中屏 921–1279px | 导航抽屉，列表与阅读区双栏 |
| 设置导航中栏 ≥921px | 固定280px，为右侧配置区预留更多宽度 |
| 窄屏 ≤920px | 列表／详情单栏流转；列表宽度 100% |
| 阅读内容 | 最大宽度 760px、居中；外层阅读区域独立滚动 |
| 顶栏控件 | 桌面高 32px，单栏高 36px；同组控件等高、垂直居中 |
| 常用圆角 | 小控件与新闻卡片6px，想法／设置卡片8px，浮层12px；特殊角色复用已有变量 |

- **移动端底部导航固定为“新闻流、稍后再看、收藏”，顺序不变。后续新增功能入口放入导航抽屉，不向底栏添加入口，除非用户明确修改这一约定。**
- **移动端顶栏主题切换使用图标，保留可访问的名称、当前主题说明，以及菜单中的完整主题名称。**
- **移动端顶栏 Agent 通知按钮仅在有待查看消息时显示；无消息时隐藏且不占位，消息已看或忽略后即时更新。桌面入口保持常显。**
- **移动端新闻列表搜索框默认收起，搜索图标位于工具栏最右侧、全部已读按钮右边；点击后在原顶行快速展开并聚焦，再次点击收起，同时清空关键词并恢复当前筛选下的新闻列表。桌面搜索框常显，墨水屏与减少动态效果模式无展开动画。**
- 主题列表搜索与新闻流共用搜索组件及上述显隐、焦点、断点和动画规则；手机搜索图标位于新建按钮右侧，搜索范围为主题名称和定义，并与主题状态筛选叠加。
- **新闻列表顶部主筛选高度自适应：桌面字号11.5px、内边距3px 9px；移动端字号12px、内边距5px 12px。二级分类在两端均为字号12px、内边距3px 8.5px、高度28px。**
- **二级分类的「全部」始终不显示数量；其余分类仅在选中时显示该分类在当前主筛选、来源与搜索范围内的完整新闻数量，未选中时仅显示名称。**
- **二级分类除「全部」外，当前范围新闻数量大于0且未选中时显示1px浅黄色边框，复用 `--favorite-border`；选中、零条或数量尚未取得时边框透明。墨水屏沿用黑色边框，选中态仍通过原有底色与文字色区分。**
- **默认排序：仅新闻流「未读」与稍后再看「待阅读」从旧到新，其余列表／筛选从新到旧。切换集合或主筛选恢复对应默认排序；分类、来源和搜索保留当前手动排序。**
- 导航抽屉收起时不显示阴影；展开时复用主题的 `--shadow-float`，墨水屏使用实色阴影。
- 桌面顶栏同步状态以窗口中线居中，左右按较宽一侧预留相等空间；控件显隐或窗口变化时同步调整，文字可省略。921–1100px时主题选择压缩为图标，手机沿用状态点与报错角标入口。
- **中栏新闻卡片按日期分组：标题左侧显示日期，右侧显示当前分类、来源、搜索及阅读状态范围内的当日新闻总数，包含尚未加载的条目。日期标题无背景，滚动时吸顶并由下一个日期接替；卡片仅显示时间。**
- 新闻流与稍后再看的底栏角标复用各自导航未读计数；零条或尚未取得计数时隐藏，超过 99 显示 `99+`，可访问名称保留完整数量。稍后再看沿用“待阅读”口径，不与新闻流的已读状态混用。
- 设置沿用同页工作台，保留九类配置和分类／详情切换，窄屏沿用列表／详情流转。新闻分类独立管理自动分类开关、未读范围与并发上限；API 管理仅管理各服务的密钥、模型与连接测试。分类名称和范围见当前组件映射。 入口采用单行紧凑布局，只保留图标、名称与箭头，移除分类搜索、次级标签、入口说明和底部提示；系统与版本排首位，新增快捷键设置。
- 定时任务作为设置分类，只读展示报告排期、运行状态与最近20条记录；复用设置卡片、字段、队列计数和新闻卡片。页面可见时每10秒刷新，离开或隐藏后停止；失败保留最近成功结果及更新时间，不覆盖未保存配置。模型与 Agent 页面通过「功能」Picker 分别配置 Chat、主题追踪、新闻总结、日报的 Runtime 与模型，选项和草稿互相独立；不再展示重复的用途说明。Codex 的自定义模型、服务商覆盖与 Profile 收入「高级设置」。
- 快捷键每项固定两个独立录入框，直接按键记录单键或组合键，保存到当前浏览器；重复绑定须即时提示冲突。无未保存更改时隐藏保存与撤销按钮；检查更新前隐藏空结果区域。底部快捷键栏可在设置中通过 toggle 开关，也可由栏右侧关闭按钮隐藏；移动端三项主导航不受该开关影响。速查与控件按键提示随保存更新，输入和弹窗内不误触全局操作。
- 全局隐藏滚动条外观，同时保留各容器原有的滚轮、触屏和键盘滚动能力。内容过长时应能到达末尾，浮层应限制在可见视口内。
- 详情返回及移动端边缘返回保留草稿、选中项和列表位置；不干扰正文滚动、文字选择、输入和 Agent 对话。

## 5. 字体与阅读层级

| 角色 | 规范 |
| --- | --- |
| 新闻主标题 | `--font-display`、`--fs-h1`，700／1.25 |
| 二级标题 | `--fs-h2`，600／1.35；设置详情标题保持 600 字重 |
| 三级标题 | `--fs-h3`（16px），600／1.4 |
| 新闻卡片标题 | `--font-display`、`--fs-card-title`，桌面14.5px／1.38、手机15px／1.4，600 |
| 正文、精读要点、已存想法 | `--font-body`、`--fs-body`（14px），行高 1.7 |
| 新闻卡片摘要／元信息 | 摘要12.5px／1.45、来源11px、时间10.5px，使用 `--fs-card-snippet/meta/time` 与 `--muted`；其他组件保留 `--fs-small`（13px）／`--fs-meta`（12px） |
| 代码与技术输出 | `--font-mono`，沿用现有对应组件的尺度 |

字体栈复用基础 Token，不引入独立页面字体。普通新闻摘要两行截断，已抓取新闻的精读核心结论完整显示。独立想法和新闻总结沿用各自已有排版，不把新闻正文尺度机械应用到所有内容。手机 Agent 输入框使用 16px，这是正文 14px 之外的既有输入控件规则。

上述尺度为默认“标准”字号。顶栏“阅读字号”提供小／标准／大／特大（90%／100%／115%／130%），通过应用层 `--reading-scale` 调整新闻列表、正文、精读、想法、总结与 Agent 消息内容；导航、按钮、设置及 Agent 输入框保持原尺度。偏好在当前浏览器保存，页面首屏恢复。手机入口使用 `Aa`，保留完整选项、当前字号说明与键盘操作；复用现有下拉组件，不改写基础字号 Token。

## 6. 当前组件契约

- **日报／周报／月报**：「日报」位于研究导航下，与主题追踪、新闻总结激活时均隐藏来源筛选；手机放在抽屉，底栏三项保持不变。中栏直接使用共享列表容器、顶部筛选与新闻卡片，顶部只有「日报、周报、月报」三个入口；早报、午报、晚报统一列在日报。右栏使用共享阅读工具栏、760px正文容器、标题、正文及阅读字号；三条以内导读、重点主题、次重点简讯、少量关键转折加粗、按需展开的来源与「本期完」构成有限阅读体验。默认不展示密集链接、选稿理由、评分、阅读进度或未读角标。报告独立于新闻已读状态，自动报告只从首次运行新版后的启用时间开始积累。日报与周报按覆盖月份折叠，月报按覆盖年份折叠，默认展开当月／当年；历史分组按需分页加载，手动补生成也归入对应周期。中栏右上角使用加号「新增日报」，在按钮旁的浮层完成设置，不占用右栏或切换手机阅读页面；早午晚报用共享日历选日期，周报选起始日并覆盖连续7天，月报选月份，仅「自定义」显示北京时间起止输入，聚焦任一端后使用同一个共享日历与小时／分钟 Picker，也支持直接输入，不使用原生日期时间弹窗；右栏顶部可删除未运行的报告，使用共享确认框。生成中显示实际阶段、分批计数和耗时，不编造完成百分比。排期与生成规则见 [定期报告](periodic-reports.md)。
- **主题追踪**：入口位于研究导航，手机通过抽屉访问；入口角标显示有未查看新闻或进展更新的持续跟踪主题数，同一主题只计一次，完整主题详情连续可见6秒后清除，零值隐藏；新闻时间线的未读新闻在来源名称旁复用卡片标签显示小写 `new`，与新闻流红点共用全局已读状态；完整主题详情连续可见6秒后，将当前快照内全部未读新闻统一标读（含未加载分页），离开或隐藏页面时停止计时；中栏直接使用新闻流的列表容器、顶部工具栏、筛选及卡片组件，左侧「全部、持续跟踪、已归档」，右侧仅加号「新建主题」。新建时保留中栏，四步进度在右栏顶部展示。右栏直接使用阅读器的固定工具栏、正文容器、标题与正文排版，创建表单使用设置页的表单组件，确认定义的多轮对话复用 Agent 消息与输入组件，不另设基础尺寸与样式。初稿需询问用户确认，支持追问与修订，仅用户点击确认后开始整理历史。工具栏放置定义、归档／恢复、删除，正文展示用底部滑块浏览的阶段里程碑与纵向新闻，没有独立当前进展区块。四步创建依次为输入主题、确认定义、整理历史、完成；历史完成后才收录新入库新闻。同一新闻允许进入多个主题，详情返回保留节点选择及阅读位置。具体组件对应和流程见组件映射。
- **新闻卡片**：内边距桌面12px、手机14px 14px 12px；选中时整圈 `1px var(--accent)` 边框、额外1px accent外圈阴影与 `--surface` 底色。重要使用 accent；稍后看使用 fg 底色／surface 文字；收藏使用现有收藏状态 Token，墨水屏转为黑白。
- **正文语言**：保留「中文精读」，「中英双语」按英文一段、中文一段交替展示，直接使用共享正文排版和阅读字号；高亮与引用分别关联原文和译文。旧译文分段不一致时保留两种全文并提示重新翻译，不强行配对。
- **阅读工具**：复用现有离散按钮；桌面高 28px、圆角 6px，移动端扩大触控区域。加入稍后再看同时标记新闻流已读，不等于已看完；取消排队不恢复未读。其余已读、看完和收藏的状态分别保存。主题纵向新闻的「重要」「稍后再看」依次位于时间左侧，使用共享纯图标变体，无背景和边框；重要使用新闻流同款旗帜与全局状态，选中后以 accent 常显，稍后再看使用时钟并在已获取正文时常显，其余在桌面卡片悬停／键盘可见焦点时显示，鼠标点击及正文返回恢复的普通焦点不使按钮常显；触屏全部常显，保留可访问名称与焦点环。
- **下拉菜单**：主题及设置共用 [SelectControls](../static/select-control.js)，保留键盘导航、触屏操作、焦点恢复、视口边界与主题持久化。
- **Agent**：收起高 42px，桌面展开高 520px 并受可用高度约束；手机为约 70% 屏高的底部面板，避开顶栏、底栏和软键盘，聚焦输入时保持展开。手机不显示顶部把手及扩大／还原窗口按钮，桌面保留扩大／还原窗口按钮。手机沿用标题栏与收起按钮，保留草稿；单纯展开不自动弹出键盘。手机展开面板使用独立于阅读器的页面顶层定位，避免阅读器位移和滚动容器裁切输入区。归档使用 28px 仅图标按钮，保留“提炼结论追加到想法”的可访问名称。输入框桌面默认两行、手机默认一行，随输入增长；通过隐藏副本测量，不把正在聚焦的控件临时缩成零高或 auto，发送按钮保持可操作。
- **想法**：展示区使用虚线边界与轻量空态入口；输入器默认隐藏，展开后保留发布、取消、草稿和快捷键。Agent 归档卡片保留身份徽标与强调色左边框。归档不设最低字数，一句话足够就只写一句；正文最多 300 字符且不超过原对话正文长度，超长自动重新压缩一次，不直接截断，没有实质内容时只提示、不新增卡片。删除按钮在桌面悬停／键盘聚焦时可用，触屏常显。
- **独立想法编辑器**：保持无重型外框的内联编辑；键盘焦点显示外圈，失焦恢复轻量外观；语法速查遵循现有焦点显示及折叠偏好。新闻想法直接复用新闻阅读器。
- **通知与反馈**：刷新和铃铛复用顶栏无边框图标按钮；通知、报错等浮层复用 surface、border-strong、radius-lg、shadow-float。上游报错面板使用16px标题及紧凑卡片尺度，高度随内容收缩、上限640px并受可见视口约束；空状态不撑满，长记录内部滚动，细则见组件映射。沿用现有互斥与定位规则，消息是否已看由真实可见状态决定。
- **顶栏任务进度**：同一个圆环汇集新闻分类、主题追踪和日报（含周报、月报）。只有新闻分类时按真实批次显示比例；涉及主题或报告时使用静态分段圆环，浮层分组展示真实阶段和错误，不混算整体百分比。任务行复用通知列表，点击进入对应内容；完成后自动移除，失败保留。长列表内部滚动，手机避开底部导航。
- **业务确认框**：复用应用内共享确认组件，沿用 `catchup-dialog` 的主题样式；默认取消，关闭等同取消，焦点约束在框内并在退出后返回可用触发项。
- **面板外部点击**：Agent 展开面板与上游信源报错面板在桌面和手机上均遵循“首次点击外部只收起，第二次点击才操作目标控件”。消费首次完整的鼠标／触屏点击，避免焦点、导航或操作穿透；面板内控件及其上层确认框保持可用，Agent 草稿保留。
- **报错面板背景**：上游信源报错面板展开时虚化整个页面背景，面板及日历保持清晰；关闭时同步移除虚化层。墨水屏不使用模糊和半透明遮罩。
- **报错面板排布**：日期输入与日历保持内容宽度靠左，日期导航保持紧凑宽度靠右；移动端仅保留前后日箭头与40px宽的「今日」，日期输入和日历仍可查看历史。统计四项等分居中，分类维度按钮等分可用区域。「全部时间／全部来源」筛选始终保持内容宽度靠左，其余筛选胶囊随空间伸缩；窄屏沿用横向滚动及计数换行，避免内容重叠。

具体选择器、状态及版本修订查阅 [当前组件映射](design-token-mapping.md)。展示真实 API 数据；示例时间、计数、模型和运行状态只用于测试。视觉调整不得擅自恢复已移除的入口、冗余信息或改变现有保存和状态同步行为。

主题右栏分区标题为「重要进展」「新闻时间线」，概览不重复展示新闻／节点统计，工具栏左侧显示真实跟踪或处理状态，右侧保留定义、归档／恢复、删除；概览不重复显示状态。紧凑排版使用共享分区卡片变体及既有间距 Token，避免卡片间距、子组件外距与内距重复叠加；具体参数见组件映射。

## 7. 主题、可访问性与品牌

- 支持浅色、深色、跟随系统、墨水屏四种选择；跟随系统的浅／深分支分别与显式主题一致。
- 主按钮与发布按钮使用 `--accent` 配合 `--accent-button-fg`；默认与悬停的普通文字对比度目标均不低于 4.5:1。新增组合按实际计算样式检查，不能只凭设计表推定合格。
- 键盘焦点保持可见，沿用 2px accent 外圈、2px 偏移，并避免被滚动容器裁切。仅图标按钮必须有可访问名称；输入、菜单和弹窗沿用现有语义与焦点管理。
- 墨水屏的状态色、收藏和高亮使用黑白实色，禁用 CSS 与相关 JavaScript 动画。其他主题尊重 `prefers-reduced-motion`，动效复用既有时长和缓动变量。
- 品牌复用 [static/brand/](../static/brand/) 的「留白书签」及原始轮廓字标，保持比例和透明负空间，不改用字体重排字标。顶栏标志 24px、字标 124×19px、间距 8px；各主题颜色、资源生成和单一可访问名称遵循品牌规范。

## 8. 修改与验证流程

1. 明确涉及的现有组件、主题、断点和状态，读取对应映射与实现；优先复用现有结构、样式及交互控制器。
2. 在正确层级修改。变更 Token 时同步规范与导出；变更组件规则时更新组件映射；变更固定约定时更新本文件。版本级产品变化再按项目流程记录 CHANGELOG。
3. 修改 [独立想法编辑器源码](../frontend/idea-markdown-editor.js) 时运行 `npm run build:idea-editor`，同步生成资产，不手工修改压缩产物。
4. 按实际影响验证：仅文档改动检查链接和差异；Token／样式改动运行 Token 检查及相关界面测试；交互改动补充或运行对应行为回归。无需为纯文档改动启动完整 UI 回归。
5. 界面变化应在真实浏览器复核受影响页面，覆盖相关主题、桌面／手机及交互状态。跨全局布局或主题的变化覆盖浅色、深色、系统浅／深、墨水屏，以及 920／921／1279／1280px 边界；检查长内容、键盘焦点和触屏操作。

常用检查入口（按改动范围选择）：

```bash
PYTHONPATH=. python3 -m pytest -q tests/test_design_tokens.py
CI=1 npx playwright test tests/ui/v004.spec.js tests/ui/design-feedback.spec.js tests/ui/design-accessibility.spec.js
CI=1 npx playwright test tests/ui/mobile-navigation.spec.js tests/ui/select-controls.spec.js
```

界面回归使用隔离测试数据，不用真实新闻库制造测试状态。截图和运行产物沿用忽略提交的 `.ui-artifacts/`、`test-results/`。交付时说明改动、验证结果和未验证范围。

## 9. Git 提交

所有 `git commit` message 必须使用简体中文，禁止纯英文提交信息；可使用 Conventional Commit 前缀，例如 `docs: 统一项目设计规范与协作约定`。其他提交、分支和交接流程参见 [交接文档](handoff/README.md) 中的 Git 流程规范。

## 10. CHANGELOG 发布分类

从 v0.1.2 之后的下一个版本开始，每个版本的 CHANGELOG 按本次实际发布的改动分类，在版本标题下依次使用 `#### feat`、`#### improve`、`#### fix` 分组，条目使用简体中文：

- `feat`：新增功能或能力。
- `improve`：已有功能的体验、性能、结构或维护性优化。
- `fix`：修复缺陷、异常行为或版本回归。

发布前核对上一发布标签到本次待发布提交的完整差异，涵盖此次推送中属于该版本的全部改动，不只总结最后一次提交，也不把未发布的计划写成已完成。相关改动可合并为一条清晰说明，按实际效果归类，不机械照搬提交前缀；无条目的分类省略。v0.1.2 及更早版本的历史记录保持原格式。
