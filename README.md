# News Reader Workbench

本地新闻阅读工作台。当前稳定版本：`v0.5.1`。版本记录见 [CHANGELOG.md](CHANGELOG.md)。

团队接手请从 [项目交接总览](docs/handoff/README.md) 开始，包含产品范围、架构接口、安装维护、数据迁移、实测结果及移交验收清单。

本项目独立维护，使用新的 Git 历史，不绑定原项目远程仓库或更新源。内部包名为 `newsreader-workbench`，界面名称保留 News Reader。

新闻状态的官方名称为 **新闻浏览状态（未浏览／已浏览）** 与 **全文阅读状态（待阅读／已看完）**。后续需求和开发说明使用这两套名称；现有界面与接口保留旧称，其对应关系和当前行为见 [产品状态语义](docs/handoff/01-product.md#状态语义)。

## 界面与功能

- 后台直接通过 opencli 采集固定新闻来源，支持每日与 A 股交易日额外时刻、立即采集及1–32路翻译并发；整批翻译完成后一次入库，原文与译文持久保存，失败可重试，关闭网页不影响后台运行。配置及升级环境见[内置采集说明](docs/native-collection.md)。
- 顶栏「采集记录」按日显示抓取、去重、纳入数据库和错误数量，每次采集合并为一批，以开始时间排列，来源明细可展开。支持日期切换和「全部信息／仅错误与提示」筛选；采集错误等待下次采集，翻译或入库提示旁可按范围重试。入库按实际完成日期统计，支持查看跨日完成的批次。
- 阅读列表保持当前批次和位置，新到新闻通过提示主动载入；末尾5秒全部已读与手动批量确认只处理原范围，新增新闻保持未浏览。
- 采集与日报共用自动维护的交易日历，平时每周检查，12月缺下一年时每天检查，缺当年时立即检查并每小时重试；已验证日历本地缓存，更新不依赖模型。
- 日报、周报和月报统一先按标题、来源与发布时间选稿，确定入选名单后再使用入选新闻的已有摘要与正文补充细节；选稿阶段看不到正文可用性，写作不能增删入选来源，长报告与失败重试遵循同一规则。
- 日报与新闻总结的折叠报道来源按新闻发布时间从旧到新排列，正确处理时区，无有效时间的来源置后；原有引用、重要／稍后再看标记与返回阅读位置保留。
- 日报、周报和月报右栏提供「已阅读」，主动点击后将正文与简讯引用的来源新闻统一设为已浏览，保留全文阅读状态；保存成功后按钮显示带勾的「已完成」，中栏卡片与右栏页眉显示「已经阅读完」，刷新和跨设备仍可恢复。
- 内置采集在入库前排除 Bloomberg 主域／子域下 `/news/videos/` 视频页。日报取材、旧快照复用及重试同样排除视频；已有历史成稿保留原样，普通文字报道不因提到视频而被过滤。
- 「信源与采集」每个信源右侧提供删除按钮，确认框显示信源、新闻日期、条数、关联数据和大小。删除当前库已有新闻及其专属关联数据，保留原始采集文件、独立研究成果和其他信源共用内容；已删除新闻通过紧凑指纹防止重新导入，同一信源的新新闻及从未删除过的补录历史仍正常收录。
- 设置「帮助说明」按新闻采集、阅读中的新新闻、新闻流显示与数据清理、阅读与本地数据分组；支持多项展开、键盘操作和展开状态保留，配置读取失败时也可查看。
- 日报、周报和月报可高亮正文、引用提问 Agent；来源默认收起，紧凑展示新闻标题、媒体、日期及重要／稍后再看按钮。点击来源标题在应用内阅读新闻，返回时保留原报告位置。新闻总结在每段后就地展开该段引用的新闻，同样支持应用内阅读和重要／稍后再看标记，与新闻流、日报同步；取消编号跳转和底部集中来源表。
- Agent 输入框默认单行，发送按钮与输入框等高；发送旁的模型图标可展开选择 Runtime、模型和推理程度，保留历史对话并从下一轮生效；生成期间不可切换，面板选择不改变全局默认模型。

界面开发先阅读 [项目设计与协作规范](docs/design-guidelines.md)，其中固定设计语言、规范优先级和检查要求；具体组件以 [当前 Token 与组件映射](docs/design-token-mapping.md) 为准，基础值参考 [v2.3.7 修订设计规范](DESIGN_SPEC_AND_TOKENS_Fix.md)。主界面使用原生 HTML/CSS/JavaScript，由 Flask 直接提供；独立想法编辑器源码的构建要求见项目设计与协作规范。

- 顶栏桌面高 52px、移动端高 50px；1280px 起采用 248px 导航、430px 新闻列表和正文最大 760px 的阅读区；921–1279px 使用导航抽屉与列表／正文双栏，920px 及以下采用列表／阅读器切换及底部导航。
- 移动端底栏始终只保留“新闻流、稍后再看、收藏”，后续新增功能入口统一放入左上角导航菜单。顶栏主题切换使用当前主题图标，展开后显示完整名称；阅读页也可直接打开导航菜单。
- 移动端新闻流、稍后再看显示各自未读／待阅读数角标，零条隐藏，超过 99 显示 `99+`。顶栏“阅读字号”（手机为 `Aa`）提供小、标准、大、特大四档，调整新闻列表、正文、想法、总结及 Agent 消息内容，并记住当前浏览器的选择；导航和按钮保持原大小。
- 移动端 Agent 通知按钮仅在有待查看消息时显示。中栏搜索默认收起，搜索图标位于工具栏最右侧；点击展开，再次点击或按 Esc 收起时清空关键词并恢复当前筛选列表，桌面搜索框常显。
- 保留新闻流、稍后再看、重要新闻、收藏、想法，以及单篇新闻导读和研究 Agent。正文可切换为「中英双语」，按英文一段、中文一段交替显示，两种语言均支持高亮和引用；旧译文分段不一致时完整分开显示，并提示可重新翻译。
- 想法页按类型呈现：新闻想法直接打开完整新闻阅读器，保留正文、高亮、精读、逐条想法和 Agent；独立想法提供可选标题、Markdown 即时编辑和保存状态，输入或粘贴常用 Markdown 语法会直接排版，切换卡片保留未保存草稿和撤销记录。
- 已抓取全文的新闻卡片在标题下完整显示右栏精读框中的核心结论；没有结论时隐藏预览，结论生成后自动更新。列表和搜索共用同一条结论，未抓取全文的卡片沿用原有摘要预览。
- 新闻总结采用独立三栏工作台：预览并锁定全部未读，使用已配置的 Agent 生成报告，成功归档后统一标读；支持搜索历史、引用追溯与 Markdown 导出。提醒、复盘与板块保留后端兼容，定期报告使用独立流程；旧文件日报入口已退役。
- 研究导航新增「日报」：早午晚报归入日报，周报、月报独立切换；日报／周报按月份、月报按年份归档，默认展开当前周期。报告采用重点主题、简讯、折叠来源与「本期完」，支持全文复制、手动生成、删除与真实进度展示；中栏时间为实际执行时间；生成用时累计所有尝试，重试等待不计入。长报告通过可恢复工作区整理全期资料、分章写作与逐章复核，支持 Codex 原生委派及 Pi 并行处理。
- 「设置 → 日报任务」可分别编辑开始生成时间及新闻窗口，观察最近排期，暂停／恢复自动生成，并查看与清理材料快照。普通停机只补晚报、周报、月报，主动暂停期间不补；材料快照每7天自动清理闲置过期内容。完整规则见 [定期报告](docs/periodic-reports.md)。
- 「设置 → 模型与 Agent」分为「日报（早／午／晚）」和「周报／月报」两组默认 Runtime、模型与推理强度。早午晚共用一组，周月共用另一组；旧配置继承原日报模型，保存后两组独立。新增报告只提供五种日期类型，移除自定义时间范围及自定义报告模型设置；已有任务与重试保留原模型。
- 模型与 Agent 设置将 Chat、主题追踪、新闻总结、日报分区展开，分别选择 Runtime 与模型，各分区独立刷新目录和测试连接，测试状态以绿／红／蓝区分成功、失败与运行中。新建报告可临时指定 Runtime、模型和推理程度，创建后绑定，最多3份并行，同一窗口复用材料快照；Codex 调用统一关闭 Fast，不修改本机 Codex 配置。
- 进入页面自动增量刷新新闻索引；支持搜索、信源筛选、排序与分页、全部标读、划词引用及融入精读区的多条想法。新闻列表按日期分组，透明标题吸顶，左侧显示日期、右侧显示当前筛选范围内的当日新闻总数（包含未加载条目）；卡片仅显示时间（`HH:mm`）。仅新闻流未读与稍后再看待阅读默认旧到新，其余默认新到旧；切换集合或主筛选恢复对应默认排序。卡片滑出顶部自动标读，列表末尾停留 5 秒标读当前加载范围。
- 中栏主筛选「全部／未读」的数量跨二级分类统计，仍遵循来源和搜索条件；二级分类的「全部」始终不显示数量，其余分类选中时显示当前阅读状态、来源及搜索范围内的完整数量（包含未加载分页）；列表、每日数量和全部已读操作限定在当前分类。未选中且有新闻的二级分类显示浅黄色边框，选中、「全部」、零条及数量尚未取得时边框透明；墨水屏使用黑色边框，数量变化及保存失败回滚同步更新。
- 顶栏显示后台采集状态和未恢复的来源错误；「立即采集」只排队后台任务。错误面板按日期查看历史记录，来源恢复后清除当前错误角标；可用率依据当日最后完成结果，入库数量按实际入库时间统计。
- 收藏页排序按钮旁提供“全部取消收藏”图标按钮，一次取消全部收藏（包括未加载及搜索、来源筛选外的条目）；单篇取消收藏仍通过卡片按钮操作。
- “全部已读”执行前显示来源或全部来源、最新未读条数及搜索条件，包含未加载的匹配新闻；确认后才标读，完成提示显示来源和实际条数。
- 新闻流滚动、重要／收藏／稍后再看联动设为已浏览时，中栏、导航及来源未读数在本地即时更新；后台合并保存，失败恢复对应计数和未读标记。服务器计数按 120 毫秒节流校准，各统计接口独立显示结果，旧响应不会覆盖更新后的状态；页面可见时每 30 秒及返回窗口时再次校准，不重新下载新闻正文或触发模型调用。
- 加入稍后再看时会自动将新闻浏览状态设为已浏览，不等于全文已看完；标记重要或收藏也会自动设为已浏览。新闻浏览状态成功保存后不可逆，取消这些标记不会回退，重复标记保留首次浏览时间；重要、收藏不影响全文阅读状态。稍后再看的全文阅读状态独立保存：所有已有正文且未标为看完的新闻都进入“待阅读”，按钮显示“全文待看”，点击标记为“已看完”；再次点击“已看完”可重新加入待阅读。在稍后再看页面主动打开“全文待看”的卡牌，正文显示后也会自动标为“已看完”；默认选中、后台刷新和抓取完成不会自动标为看完。排队中可取消并恢复“稍后再看”；已开始的抓取继续执行，完成后进入“全文待看”；抓取失败点击重试。现有按钮和“全部看完”仍可显式完成阅读；标为已读／未读快捷键及其设置、提示和旧自定义绑定已移除，`m` 不再改变任何阅读状态。
- 支持浅色、深色、跟随系统、墨水屏主题；设置采用同页工作台：左栏导航、中栏九类配置及帮助说明入口、右栏配置表单或帮助内容；双栏／三栏布局的设置中栏宽 280px，系统与版本位于首位。保存和撤销仅在有实际改动时显示，手机标题与按钮保持同排。
- 快捷键：`w/s` 或 `↑/↓` 上下浏览、`a/←` 重要、`d/→` 稍后、`f` 收藏、`q` Agent、`/` 搜索、`,` 设置、`?` 帮助。设置 → 快捷键可为每个操作直接录入最多两个快捷键，支持组合键、冲突提示、单独清除和恢复默认；底部快捷键栏可通过 toggle 或右侧关闭按钮隐藏，偏好保存在当前浏览器。
- 移动端新闻／想法详情及设置子页面支持从左侧 40px 内向右滑动超过 72px 返回各自列表，跟手露出底层列表并保留草稿与列表位置；正文纵向滚动、选中文字、输入控件及 Agent 对话不触发返回。

实现说明见 [docs/ui-refactor.md](docs/ui-refactor.md)，设计落地与保留差异见 [Token 与组件映射](docs/design-token-mapping.md)。生产页面使用真实 API；设计示例新闻仅用于测试预览。

品牌采用「留白书签」标志和原版轮廓字标，已接入顶栏、浏览器 favicon 与主屏幕图标，支持浅色、深色和墨水屏。素材来源、维护与验证记录见 [品牌资源接入](docs/brand-assets.md)。

## 安装与启动

需要 Python 3.10+。新闻研究 Agent 另需 Node.js 24+，及已安装、配置的 Pi 或 Codex CLI。

在项目目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
npm ci --ignore-scripts
./启动NewsReader.command
```

macOS 也可在 Finder 中双击 `启动NewsReader.command`。脚本优先使用本项目 `.venv`，检查依赖后自动停止同一项目的旧受管实例，待其退出再启动新实例，并在健康检查通过后打开浏览器；旧实例正在更新时先等待更新安全结束。对应终端入口为 `python3 launcher.py --replace-existing`。`python3 updater.py --serve` 保留复用现有健康实例的行为，也可用 `python3 app.py` 直接启动。

默认端口为 `8080`。Finder 启动器每次启动都会分别检测独立 Tailscale 客户端和 Surge 的当前状态与地址：优先使用正在运行且可绑定的客户端地址，其次使用已启用入站访问的 Surge 节点，都不可用时自动使用 `127.0.0.1`。Surge 的用户态地址用于远程访问，本机服务监听 `127.0.0.1` 接收其转发。支持从 PATH、macOS 应用包和常见安装目录寻找 CLI，无需在不同机器上修改或保存 IP。显式设置的 host 保持优先。与其他本机服务并行运行时可指定另一端口：

```bash
NEWS_READER_HOST=127.0.0.2 NEWS_READER_PORT=8081 ./启动NewsReader.command
```

若旧启动器已退出但服务仍占用目标端口，启动脚本会核验用户身份、项目路径和进程启动信息后清理本项目遗留的 `app.py`；不会因端口被占用而结束其他项目或程序。

安装并配置 `opencli` 及现有采集适配器，用于内置新闻采集和正文抓取。详见 [内置采集说明](docs/native-collection.md)。Node 依赖使用锁文件中的固定版本，不会在启动时自动安装或升级。

Pi 日报需要当前项目内的 SDK 依赖。若提示「Pi 运行依赖不可用」，在当前项目目录执行 `npm ci --ignore-scripts`，重启应用后重试原报告；仅全局安装 Pi CLI 不能补齐项目依赖。

正文抓取兼容 opencli 2.x 的 `ok/data/error` JSON 包装及旧版直接返回的列表／对象。超时、浏览器导航或连接中断等临时故障每轮最多尝试 3 次，重试间隔为 5 秒、15 秒；登录受限、空正文与格式错误不会自动反复请求。任务尝试次数和下次执行时间保存在数据库中，重启后恢复已退出进程留下的任务；达到上限后显示失败，可手动重新抓取。重复提交不会重置正在执行或等待重试的任务。

## 数据与配置

- 新闻由内置 opencli 任务采集，原文持久暂存，整批翻译完成后一次入库；不再扫描 Markdown 或配套 JSON。
- 默认每日 00:01、04:00、08:00、12:00、18:00、21:00 采集，A 股交易日额外 09:00、10:00、11:00、13:00、14:30；北京时间，可在设置中修改。后台服务运行即可，关闭网页不影响。
- 直接兼容原 SQLite 数据库，保留新闻 ID、阅读状态、稍后再看、收藏、想法及已缓存正文／中文精读。数据库选择顺序保持原版行为：`NEWS_READER_DB_PATH` → 设置中的数据库路径 → 已存在的父目录 `news_index.sqlite3` → 项目内新库。原库位于其他目录时，在设置中选择后重启即可，无需导出或重建。
- 本地配置位于 `app_settings.json`，不纳入 Git。模型与信源可在设置工作台配置。
- Keychain 使用独立账号 `newsreader-workbench`。原项目保存的 DeepSeek 密钥不会自动迁移；请在新项目设置中重新保存，或显式设置 `DEEPSEEK_API_KEY`。
- Pi/Codex 沿用本机 CLI 的登录与配置；应用会话数据库和临时目录独立保存，不迁移旧项目会话。
- 数据库、缓存、密钥、虚拟环境、`node_modules` 和测试产物不纳入 Git。

可用环境变量：

| 变量 | 用途 |
| --- | --- |
| `NEWS_READER_HOST` / `NEWS_READER_PORT` | 服务监听地址和端口 |

## 新闻研究 Agent

设置中可选择 Pi 或 Codex，分别保存模型、provider、推理强度及连接选项。Codex 获取过的模型目录和推理档位会缓存到本地，刷新页面或重启后可继续选择；“刷新模型目录”用于更新候选，失败时保留上次成功结果。Pi 则在进入模型设置、切换为 Pi、返回窗口或手动刷新时重新读取可用凭据，目录整体替换，空目录也生效；失效的已保存选择只显示提示，不重新加入候选。Pi 登出不会删除环境变量、自定义配置或 API 管理中的独立密钥。Pi 推理强度按模型能力提供，分别用于 Chat、主题追踪、新闻总结和日报，`off` 表示关闭可选推理。设置中的 DeepSeek 密钥以掩码显示，可更新或删除，并可获取和测试翻译模型。新会话及未手动选模型的空会话使用当前保存的默认配置；已有对话保留各自会话的配置。发送按钮旁的「当前会话模型」图标可临时修改 Runtime、模型和推理程度，仅影响当前会话后续轮次。新会话重新使用设置中的默认配置，其他新闻／报告不继承临时选择；返回原会话保留其选择。支持流式状态、停止、重试、新会话及归档到想法。连接测试使用当前功能未保存的模型、服务商和推理强度发送一次简短请求，不验证完整 Agent 的工具能力；修改选择后旧结果失效。

输入框默认一行，随输入与粘贴增高，发送按钮保持等高；桌面最高约八行、手机约五行，并受可见视口限制，超出后在框内滚动。桌面 Enter 发送、Shift + Enter 换行；手机 Enter 换行，点击发送按钮或 Ctrl／Cmd + Enter 发送。切换新闻与发送失败会保留包含换行的草稿。输入框关闭历史提问自动补全，发送后立即清空已发问题。准备会话、提交请求和生成回复期间均可继续编辑下一条草稿，当前任务结束后再发送；返回结果不会清空新草稿，提交失败时仅恢复尚未被新编辑替代的问题。

新闻有标题和链接时，即使全文未抓取、排队中或抓取失败，也可在 Agent 面板输入问题。面板显示“引用新闻标题”与“尚未提供全文”；模型只收到该新闻的标题资料，不会自动发送问题或触发正文抓取。全文后来就绪时，已有对话保留原资料与模型，可新建会话读取全文；尚无消息的空会话会在首次发送前采用当前资料。标题聊天沿用临时会话保存期限、检索能力及回复通知。

独立想法的 Markdown 语法速查在标题、正文或速查区获得焦点时显示，离开后隐藏；示例仍可点击复制，展开／收起偏好会保留。

Pi 使用 OAR/Pi SDK 或兼容 CLI 路径。Codex 使用本机 CLI；应用不复制账号凭据，显式设置 `read-only` 文件沙盒和 `approval_policy=never`。新闻研究任务继续启用 Codex 实时网页搜索（`web_search="live"`）；Pi 沿用本机工具、扩展和 MCP，是否检索由用户问题与原生运行时决定。实际联网能力仍取决于 provider、网络与本机工具配置。未配置 CLI 或凭据不影响基础阅读。

新闻对话首轮仅提供标题、来源、日期、链接、正文及本轮问题／划线引用；没有全文时只标注资料状态。后续沿用同一个原生会话，仅追加新问题和新引用，不重复发送新闻或应用规则。确需迁移／重建时才补入原新闻快照及已保存的对话、引用。旧同步接口使用同一套资料格式。应用不额外规定回答语言、格式、讨论范围、检索步骤或核查措辞，也不启用 Pi 的软预算提示词注入；保留 300 秒任务硬超时、停止及原生运行时的权限和指令。已有会话仍保留过去发送的规则，不改写其历史；新会话从首轮使用精简后的输入。

归档综合整场对话中仍然有效的主要认识，覆盖前段、中段和后段的讨论，保留关键依据、适用条件与未解决问题。只有明确被纠正或取代的观点才更新，后续转移话题或局部追问不代表早期认识失效；不把最后一条回答当作整场摘要。用户划线引用与问题分字段传输，在面板中显示独立引用块；模型提示词逐行添加 `>` 并单独标注用户问题，历史重放也保留引用。归档携带 `agent_session_id` 时直接读取服务端保存的会话及引用，不依赖浏览器消息副本；仍在生成时拒绝归档。旧同步客户端没有此 ID 时继续使用提交的完整消息。支持最多 200 条消息、单条 20000 字符、引用 4000 字符；服务端会检测超过页面读取上限的会话，超限明确报错而不截断。归档按实际主题分短段，不加标题或固定栏目，通常 200—600 字，多主题讨论可扩展至最多 2000 字符；以独立想法卡片追加，不改变原对话和历史归档。

Agent 会话默认保留 72 小时，可在设置中改为 24 小时；运行中的任务不被 TTL 清理。应用仅保存自身会话映射，不删除本机 Codex 全局历史。连接失败会显示实际错误，不使用演示成功结果。

顶栏上游报错入口会展开非模态下拉，可切换日期、按时间或来源分类、筛选并复制日志；日期可直接输入 YYYY-MM-DD 或使用主题日历，支持月份切换、方向键和 Enter 选择，只能选到今天。非法日期会就地提示，保留当前记录。Escape 先关闭日历，再关闭报错下拉；外点关闭，和 Agent 通知同时只显示一个。设置中的更新检查以独立结果区显示结论，说明与检查时间分开呈现。

设置中的「API 管理」按 DeepSeek、OpenCode Go 订阅两个分区展开，分别管理密钥、翻译模型和连接测试，并说明使用位置与失败处理。原普通 OpenCode 入口由 Go 订阅入口替代。Jev 的密钥、模型和测试位于「新闻分类」，与自动分类开关、范围和并发一起管理；它使用 [TypeSafe 原生接口](https://docs.typesafe.ai/api/system-one)，默认 `jev-latest`，同时供新闻分类、主题归属与重要进展筛选使用。

「正文翻译」可选择首选 DeepSeek 或 OpenCode Go 订阅，并独立设置「失败后切换其他 API」与「API 均失败后尝试 Pi」（默认均开启）。首选 Go 时依次尝试 Go → DeepSeek → Pi，关闭某级后备后跳过该级。DeepSeek 沿用 `llm.translation.model`，Go 使用 `api_models.opencode-go.model`；旧 `opencode` 首选与模型自动归并到 Go，已有明确的 Go 模型优先。保存后新翻译和手动重新翻译采用新策略，已有译文保留。Pi 使用 Chat 保存的 Pi 服务商与模型，即使 Chat 当前使用 Codex；仍须安装 Pi 并具备可用凭据。X 正文也使用同一翻译顺序，X 评论总结仍单独使用 DeepSeek。

直连翻译由 Python 工作线程完成：读取已抓取正文，构造包含翻译要求的消息，经 OpenAI 兼容 SDK 向选定服务发送 HTTP 请求，再解析并校验中文正文、精读要点和结论后存入数据库。脚本负责流程和校验，译文由模型生成，不需要浏览器或 Agent。DeepSeek 使用严格函数参数输出；Go 使用 JSON 文本输出，避免传入 DeepSeek 专属参数。鉴权失败、超时、非法结构、非中文正文或截断结果会触发后备；全部失败则显示失败状态，原文仍可阅读和重试。

OpenCode Go 使用[订阅接口](https://opencode.ai/v2/docs/console/go/)：目录为 `https://opencode.ai/inference/go/v1/models`，翻译和测试为 `https://opencode.ai/inference/go/openai/v1/chat/completions`。沿用原 OpenCode 分区的 `OPENCODE_API_KEY` 密钥槽；密钥须属于开通 Go 的账户。API 管理只保留一个订阅分区，不直接调用普通 OpenCode 按量接口。Go 请求携带本应用标识和独立会话标识；额度或权限不足按已保存开关切换后备。目录过滤免费模型与明确不支持 Chat Completions 的条目，Pi 的其他协议模型不受影响。

模型连接测试单次执行，不自动重试或改选模型；失败展示服务端明确的限制类型及建议等待时间。密钥保存在系统钥匙串，环境变量 `DEEPSEEK_API_KEY`、`TYPESAFE_API_KEY`、`OPENCODE_API_KEY` 优先，不写入设置 JSON。API 管理的密钥不再作为共享环境变量注入 Pi；Pi 功能继续使用本机登录或用户显式设置的环境变量，模型在「模型与 Agent」选择。已有 Pi 登录不被改写。

各分区独立保留模型／密钥草稿和测试结果，获取目录失败时保留上次结果。底部用途说明显示已保存的功能配置。Jev 临时失败会退避重试，限流降低并发，凭据失效暂停；已有分类及主题内容保留。Chat 与主题研究可重试，积压新闻总结失败不标读；日报最多尝试3次，之后可手动重试，沿用创建时绑定的模型。这些功能的重试不自动切换服务商，已有新闻、译文和报告可继续阅读。

OpenCode Go 与 Jev 的手动目录请求使用 25 秒网络超时，适用于连接、HTTPS 握手与响应读取。失败时分别提示超时、HTTP 鉴权／权限问题、网络不可达或响应解析失败；握手超时不表示密钥无效。错误提示不回显密钥或原始响应，修复后需重启后端生效。

全部已读、Agent 新建／清空、删除 API 密钥、更新重启、放弃设置刷新及删除独立想法使用统一主题确认框，默认聚焦“取消”。确认过程中目标或范围变化时会提示重新操作。浏览器离页保护与系统选库窗口仍保留。

### Agent 回复通知

顶栏右侧的铃铛会提示待查看的 Agent 回复；收起面板、切换新闻、刷新或重开应用后仍可查看。点击铃铛，在下拉框中选择通知，即可回到对应新闻、展开原会话并定位该轮回复；即使新闻不在当前筛选或已加载列表中也可跳转。同一会话的多轮待看消息合并显示。

只有窗口在前台、对应会话展开且该回复实际出现在可见区域时，才清除对应通知。仅打开通知列表、停在旧消息处或跳转失败都会保留通知；“全部标为已读”只处理点击时列出的消息，新到回复保留。清除通知不会改变新闻的已读、收藏或重要状态。通知在前台约每5秒更新，切回窗口时立即刷新，后台暂停轮询。

本轮失败或服务重启中断会显示“本轮未完成”；主动停止不通知，升级前已经完成的历史任务不补发。通知不延长会话原有保存期限；新闻不可访问或会话过期／被删除时，会说明原因并保留通知，可手动“忽略”。不同新闻库的新增会话、任务和通知分别保存归属，即使共用 Agent 库也不会混用。升级前尚无库归属的旧会话仅按新闻ID及URL兼容读取，实际继续提问时才关联当前库，历史任务不补归属或通知。

## 积压新闻总结

左侧「新闻总结」进入历史报告工作台；新闻流中栏顶部栏保持原样。点击「总结并全部已读」先预览，再确认启动。预览有效 15 分钟，包含已关闭信源，排除 Bloomberg 视频；日期、条数与输入大小限制只决定纳入报告的材料，成功归档后会标读全部锁定未读，范围外条数会提前明确展示。失败、取消及新到新闻不受本批标读影响。

设置 → 积压新闻总结范围提供最多自然日（默认 20，含起止）与最多未读条数（默认 6000）。保存后用于下一次预览，运行中批次保持原快照。总结使用「模型与 Agent」中的 Pi/Codex 配置，与单篇 DeepSeek 翻译独立。历史报告及引用保存在当前新闻数据库中；执行进度可在刷新页面后恢复查看。

## 主题追踪

左侧入口显示有未查看新闻或重要进展更新的主题数量，同一主题只计一次，归档主题不计入。查看具体主题详情后清除该主题的更新标记，零条隐藏；仅打开列表、编辑定义或查看单篇新闻不会清除。

在左侧研究导航选择「主题追踪」，点击顶栏加号输入事件。应用先联网生成定义，并询问是否确认。确认页支持与 Agent 多轮对话，可追问细节、协商修订名称、范围、横向收录规则及历史起点，也可展开直接编辑当前定义。对话与修订会保存，刷新后可继续；只有点击「确认并整理历史」才联网梳理历史，聊天中表示同意不会自动开始。新主题统一使用重要进展，不再提供月度总结模式。完成后才开始收录之后首次入库的相关新闻，不回扫本地历史库，也不补收创建期间的新闻。

中栏顶栏左侧可筛选「全部、持续跟踪、已归档」，右侧为仅加号的「新建主题」，点击后保留中栏列表，创建步骤放在右栏顶部。全部包含创建中的主题；持续跟踪只显示已完成且未归档的主题。详情中可归档或恢复跟踪：归档保留当前资料并停止收录，恢复后只接收之后首次入库的新闻，不补收归档期间的内容。

中栏搜索框按主题名称与定义过滤，并与上述状态筛选叠加；桌面常显，手机点击搜索图标展开，收起时清空关键词。搜索沿用新闻流的样式、快捷键与交互，不影响右栏内容或新建主题草稿。

右栏固定工具栏左侧显示跟踪及处理状态，右侧提供定义、归档／恢复及删除。主题创建后仍可点击「定义」编辑名称、定义、纳入／排除范围和横向收录规则。保存只影响之后新入库的新闻，已有报道与节点保留，排队中的旧新闻继续使用原规则。定义多行编辑框按内容显示2–7行，纳入／排除范围等高，无修改时隐藏取消与保存。上方「重要进展」用底部滑块横向浏览，也可全部展开为从左到右逐行排列的时间线，下方「新闻时间线」按日期展示最新在前的具体报道。历史通常整理为5–10个、最多12个节点，已有过细的节点可通过「精简进程」合并并保留新闻关联；先生成可放弃的预览，确认应用后才替换节点并开始一个自然月间隔。支持恢复最近一次精简前的节点，同时保留后来新增的报道和节点；旧版已完成的精简因没有快照不提供恢复。失败可重试。节点显示实际关联报道数：有报道时点击筛选，无报道仅展示节点说明并保留下方列表；滑块不改变选中或筛选。直接点击报道标题／摘要，在主题右栏使用原有阅读器；中栏位置与状态不变，返回时保留时间线位置。新闻卡片时间左侧提供无背景、无边框的稍后再看图标；已获取正文时常显，其余桌面悬停／聚焦显示，触屏全部常显。删除主题只删除档案和派生关系，原始新闻、收藏及阅读状态保留。

主题归属由「新闻分类」设置中的 Jev 根据标题和现有摘要判断，与新闻分类同阶段执行；同一新闻可以进入多个主题。进入主题后，Jev 再根据横向收录规则及已有节点筛选重要进展；新增节点直接使用新闻标题和摘要，重复进展关联已有节点，不收录或信息不足的新闻仍保留在纵向新闻流。这两层判断共用 Jev 配置、并发及限流，不受普通分类开关或未读范围限制，也不获取正文。创建时联网研究和手动精简使用全局 Agent；新主题后续不自动调用 Agent、不联网寻找进展。既有月度主题保留其资料与兼容处理。未配置、失败和中断会显示状态，可配置后重试。

## 新闻分类

新闻流提供「全部、中国、AI、政治与国际、经济与金融、商业、科技与科学、其他」八个筛选项；每篇新闻保存一个分类。「商业」对应规则中的「商业与产业」。「全部」包含待分类和失败新闻，「其他」只包含已判定为其他主题的新闻。

设置 → 新闻分类以环形图对比已分类与全部新闻，显示数量、比例及未分类数；图表始终覆盖整个新闻库。下方单独展示按已保存「全部／仅未读」配置处理的队列计数，保留限流与异常提示、手动刷新和失败重试。分类完成或关闭后仍可查看，刷新不覆盖未保存设置。

分类沿用第二轮标题评估规则（`classification/rules.json`）：先判断主要主题；只有 AI 模型、应用、研究、产品或算力本身的技术能力进展归 AI。交易行情归经济与金融，监管及国际依赖归政治与国际，企业经营归商业。非 AI 新闻再判断中国是否为核心事件的直接主体或主要对象；单纯被引用或被呼吁不构成中国主体。模型概率与复核标记供排查使用，不代表准确率。

配置 Jev 并启用自动分类后，通过 `python3 app.py` 或项目启动器启动应用，后台自动处理历史队列；整批新闻入库后排队新标题，已有分类继续复用；历史队列按当前规则处理。默认使用「新闻分类」设置中保存的 Jev 模型（未设置时 `jev-latest`）；需要固定评估模型时选择 `jev-1.14.0`。分类表独立保存，不改写新闻浏览状态及收藏状态。未配置密钥时队列等待；网络、响应格式及一般服务错误最多尝试 4 次，失败后在顶栏分类进度的悬停卡片内重试；凭据或模型错误暂停调用，修复设置后重试。重试不会重新请求已完成的分类。

在「设置 → 新闻分类」通过 toggle 启停自动分类，并调整「分类并发上限」，默认 8，范围 1–32，保存后立即生效。降低上限时允许已经发出的请求完成，后续请求遵守新上限。配置保存为 `classification.concurrency`；直接修改设置文件需重启服务。

自动分类关闭后，未读范围与并发上限立即置灰禁用且保留原值；保存后停止领取新分类任务，主题归属继续处理，进行中的请求允许完成，已有分类与队列保留，顶栏分类进度隐藏。开关保存为 `classification.enabled`，默认开启；旧版 Jev 分类参数会自动迁移到独立 `classification` 配置。

同一面板提供「仅对未读新闻分类」，默认关闭。开启并保存后，后台只领取当前未读的新闻，进度与失败重试也按未读范围统计；已在处理的请求继续完成，已有分类保留。已浏览新闻的待处理记录继续保留；关闭开关后继续补齐已浏览新闻，无需将其改回未浏览。未读口径沿用新闻流的 `read_at` 状态，与「稍后再看」的完成状态独立。配置保存为 `classification.unread_only`，直接修改设置文件需重启服务。

遇到 HTTP 429／529，整个分类服务统一暂停新请求，并把有效并发减半（最低 1）；同一批在途请求的多次限流只降一次。共享等待从 5 秒指数增加，默认退避最长 300 秒；服务端 `Retry-After` 指定更长等待时优先遵守。冷却结束后，连续成功且稳定至少 30 秒，再逐级增加并发至设置上限。限流不消耗单篇新闻的失败次数，队列会继续等待；悬停卡片显示实际并发与冷却时间，点击重试不会绕过限流等待。

顶栏 Agent 通知旁的空心圆汇集新闻分类、主题追踪和报告生成任务；卡片按任务列出模型、阶段和错误。只有分类任务时显示分类进度：一圈代表此次分类批次的全部新闻，主题色圆弧代表此次已完成部分，历史已完成新闻不计入。刷新、服务重启及失败重试保留本轮进度；处理中新增的新闻并入本批，结束后再出现新任务则开始下一批。鼠标悬停、键盘聚焦或触屏轻触可查看数量、范围与运行状态。处理中每 2 秒刷新真实计数，切换集合后继续显示；全部成功完成后自动隐藏，有失败项时保留重试入口。进度更新不重载新闻列表。

筛选先于服务端分页并覆盖搜索、当前计数与全部已读；侧栏总数仍为全局范围。历史初始化可能耗时并产生 Jev 调用费用，补标期间可继续阅读。

## 版本与更新

版本统一为 `v0.5.1`；npm 包版本为 `0.5.1`。更新源明确配置为本项目的 `https://github.com/xusz12/NewsReader2.git`，不会自动读取其他远程仓库。

在设置 → 系统状态与版本升级中点击「检查更新」，会重新读取 GitHub 的稳定版本 tag（`vN.N.N` 或 `vN.N.N.N`，不含预发布后缀），显示目标版本、检查时间和本地更新条件。没有稳定版本、已是最新版和本地版本领先会分别提示。GitHub 连接或访问限制导致检查失败时可稍后重试。

使用 `启动NewsReader.command` 或 `python3 updater.py --serve` 启动，并保持项目位于干净分支，才能确认更新。未保存的设置需要先保存或重置；未提交的源码或未忽略文件需要先妥善处理。ZIP 下载、detached HEAD 和本地分叉需在终端处理，应用不会自动丢弃修改。

确认后，更新器校验标签提交、目标版本号和更新源，执行快进更新、重启和健康检查；失败时尝试恢复旧提交并重启。数据库、配置、缓存与生成素材已忽略，不阻碍正常更新；目标版本与本地忽略文件同名时会拒绝覆盖。界面显示中文进度，刷新或重新打开设置可恢复查看，完成后点击「刷新使用新版本」。依赖版本发生变化时，仍需按安装说明准备运行依赖；更新器不自动安装依赖。

本地生成的 `output/`、日志、覆盖率报告、编辑器配置和 `.env` 等不纳入 Git，正式应用资源、锁文件、测试与文档继续纳入版本管理。发布新版本时需保证版本元数据一致，并推送对应稳定 tag；仅修改本地版本号不会产生远端更新。
