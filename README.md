# News Reader Workbench

本地新闻阅读工作台。当前稳定版本：`v0.2.1`。版本记录见 [CHANGELOG.md](CHANGELOG.md)。

团队接手请从 [项目交接总览](docs/handoff/README.md) 开始，包含产品范围、架构接口、安装维护、数据迁移、实测结果及移交验收清单。

本项目独立维护，使用新的 Git 历史，不绑定原项目远程仓库或更新源。内部包名为 `newsreader-workbench`，界面名称保留 News Reader。

## 界面与功能

界面开发先阅读 [项目设计与协作规范](docs/design-guidelines.md)，其中固定设计语言、规范优先级和检查要求；具体组件以 [当前 Token 与组件映射](docs/design-token-mapping.md) 为准，基础值参考 [v2.3.7 修订设计规范](DESIGN_SPEC_AND_TOKENS_Fix.md)。主界面使用原生 HTML/CSS/JavaScript，由 Flask 直接提供；独立想法编辑器源码的构建要求见项目设计与协作规范。

- 顶栏高 52px；1280px 起采用 248px 导航、430px 新闻列表和正文最大 760px 的阅读区；921–1279px 使用导航抽屉与列表／正文双栏，920px 及以下采用列表／阅读器切换及底部导航。
- 移动端底栏始终只保留“新闻流、稍后再看、收藏”，后续新增功能入口统一放入左上角导航菜单。顶栏主题切换使用当前主题图标，展开后显示完整名称；阅读页也可直接打开导航菜单。
- 移动端新闻流、稍后再看显示各自未读／待阅读数角标，零条隐藏，超过 99 显示 `99+`。顶栏“阅读字号”（手机为 `Aa`）提供小、标准、大、特大四档，调整新闻列表、正文、想法、总结及 Agent 消息内容，并记住当前浏览器的选择；导航和按钮保持原大小。
- 保留新闻流、稍后再看、重要新闻、收藏、想法，以及单篇新闻中文精读和研究 Agent。
- 想法页按类型呈现：新闻想法直接打开完整新闻阅读器，保留正文、高亮、精读、逐条想法和 Agent；独立想法提供可选标题、Markdown 即时编辑和保存状态，输入或粘贴常用 Markdown 语法会直接排版，切换卡片保留未保存草稿和撤销记录。
- 已抓取全文的新闻卡片在标题下完整显示右栏精读框中的核心结论；没有结论时隐藏预览，结论生成后自动更新。列表和搜索共用同一条结论，未抓取全文的卡片沿用原有摘要预览。
- 新闻总结采用独立三栏工作台：预览并锁定全部未读，使用已配置的 Agent 生成报告，成功归档后统一标读；支持搜索历史、引用追溯与 Markdown 导出。日报、提醒、复盘、跟踪、板块仍保留原后端兼容。
- 进入页面自动增量刷新新闻索引；支持搜索、信源筛选、排序与分页、全部标读、划词引用及融入精读区的多条想法。新闻列表不再显示日期分组标题，卡片显示完整日期与时间（`YYYY-MM-DD HH:mm`）。新闻流默认未读、旧到新；卡片滑出顶部自动标读，列表末尾停留 5 秒标读当前加载范围。
- 桌面顶栏中央合并 DailyNews 索引同步状态、最近同步时间与当日报错数量；移动端保留状态点和紧凑数量，无报错时隐藏数字。报错弹窗保持固定尺寸并适配视口，标题和日期区固定，内容独立滚动；每次打开显示今日，支持日历选日、前后一天、最近三天快捷切换、时间／来源分类及日志复制。点击“今天”重新读取当日记录。指标展示当日抓取可用率、异常来源、已入库资讯及当日报错；可用率按日报中的可用来源占全部已记录来源计算，无更新计为可用，发生过报错的来源计为异常；入库数按采集文件日期统计，切换历史日期时同步变化，无抓取记录时可用率显示“—”。
- 收藏页排序按钮旁提供“全部取消收藏”图标按钮，一次取消全部收藏（包括未加载及搜索、来源筛选外的条目）；单篇取消收藏仍通过卡片按钮操作。
- “全部已读”执行前显示来源或全部来源、最新未读条数及搜索条件，包含未加载的匹配新闻；确认后才标读，完成提示显示来源和实际条数。
- 新闻流滚动标读和手动切换已读时，中栏、导航及来源未读数在本地即时更新；后台合并保存，失败恢复对应计数和未读标记。服务器计数按 120 毫秒节流校准，各统计接口独立显示结果，旧响应不会覆盖更新后的状态；页面可见时每 30 秒及返回窗口时再次校准，不重新下载新闻正文或触发模型调用。
- 稍后再看使用统一状态：所有已有正文且未标为看完的新闻都进入“待阅读”，按钮显示“全文待看”，点击标记为“已看完”；再次点击“已看完”可重新加入待阅读。在稍后再看页面主动打开“全文待看”的卡牌，正文显示后也会自动标为“已看完”；默认选中、后台刷新和抓取完成不会自动标为看完。排队中可取消并恢复“稍后再看”；已开始的抓取继续执行，完成后进入“全文待看”；抓取失败点击重试。`m` 和“全部看完”仍可显式完成阅读。
- 支持浅色、深色、跟随系统、墨水屏主题；设置采用同页三栏工作台：左栏导航、中栏六类设置及搜索、右栏配置表单。
- 快捷键：`w/s` 或 `↑/↓` 上下浏览（兼容 `k/j`）、`m` 标读、`a/←` 重要、`d/→` 稍后、`f` 收藏、`q` Agent、`/` 搜索、`,` 设置、`?` 帮助。
- 移动端新闻／想法详情及设置子页面支持从左侧 40px 内向右滑动超过 72px 返回各自列表，跟手露出底层列表并保留草稿与列表位置；正文纵向滚动、选中文字、输入控件及 Agent 对话不触发返回。

实现说明见 [docs/ui-refactor.md](docs/ui-refactor.md)，设计落地与保留差异见 [Token 与组件映射](docs/design-token-mapping.md)。生产页面使用真实 API；设计示例新闻仅用于测试预览。

品牌采用「留白书签」标志和原版轮廓字标，已接入顶栏、浏览器 favicon 与主屏幕图标，支持浅色、深色和墨水屏。素材来源、维护与验证记录见 [品牌资源接入](docs/brand-assets.md)。

## 安装与启动

需要 Python 3.10+。新闻研究 Agent 另需 Node.js 24+，及已安装、配置的 Pi 或 Codex CLI。

在项目目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
npm ci --ignore-scripts
./启动NewsReader.command
```

macOS 也可在 Finder 中双击 `启动NewsReader.command`。脚本优先使用本项目 `.venv`，检查依赖和服务健康后打开浏览器；同一项目重复启动会复用自身服务。终端等价入口为 `python3 updater.py --serve`，也可用 `python3 app.py` 直接启动。

默认端口为 `8080`。Finder 启动器在未指定 host 时会尝试可用的 Tailscale IPv4，否则使用 `127.0.0.1`。与其他本机服务并行运行时可指定另一端口：

```bash
NEWS_READER_HOST=127.0.0.2 NEWS_READER_PORT=8081 ./启动NewsReader.command
```

可选安装并配置 `opencli`，用于新闻正文抓取。Node 依赖使用锁文件中的固定版本，不会在启动时自动安装或升级。

正文抓取兼容 opencli 2.x 的 `ok/data/error` JSON 包装及旧版直接返回的列表／对象。超时、浏览器导航或连接中断等临时故障每轮最多尝试 3 次，重试间隔为 5 秒、15 秒；登录受限、空正文与格式错误不会自动反复请求。任务尝试次数和下次执行时间保存在数据库中，重启后恢复已退出进程留下的任务；达到上限后显示失败，可手动重新抓取。重复提交不会重置正在执行或等待重试的任务。

## 数据与配置

- 新闻输入为 `dailyFreshNews_*.md`；同目录存在有效的同名 `.newsreader.json` 时优先读取结构化数据，否则回退到 Markdown。应用不写回原始新闻文件。
- 默认输入目录与原版一致，仍为本机 `DailyNews`，递归扫描各年份／月份子目录。可通过原有 `NEWS_READER_DAILY_NEWS_DIR` 指定，不需要改变采集脚本、文件命名或目录结构。
- 直接兼容原 SQLite 数据库，保留新闻 ID、阅读状态、稍后再看、收藏、想法及已缓存正文／中文精读。数据库选择顺序保持原版行为：`NEWS_READER_DB_PATH` → 设置中的数据库路径 → 已存在的父目录 `news_index.sqlite3` → 项目内新库。原库位于其他目录时，在设置中选择后重启即可，无需导出或重建。
- 本地配置位于 `app_settings.json`，不纳入 Git。模型与信源可在设置工作台配置。
- Keychain 使用独立账号 `newsreader-workbench`。原项目保存的 DeepSeek 密钥不会自动迁移；请在新项目设置中重新保存，或显式设置 `DEEPSEEK_API_KEY`。
- Pi/Codex 沿用本机 CLI 的登录与配置；应用会话数据库和临时目录独立保存，不迁移旧项目会话。
- 数据库、缓存、密钥、虚拟环境、`node_modules` 和测试产物不纳入 Git。

可用环境变量：

| 变量 | 用途 |
| --- | --- |
| `NEWS_READER_HOST` / `NEWS_READER_PORT` | 服务监听地址和端口 |
| `NEWS_READER_PYTHON` / `NEWS_READER_NODE` | Python / Node 可执行文件 |
| `NEWS_READER_DAILY_NEWS_DIR` | 新闻输入目录 |
| `NEWS_READER_DB_PATH` | 显式数据库路径，优先于设置 |
| `NEWS_READER_APP_SETTINGS_PATH` | 应用设置文件 |
| `NEWS_READER_MEDIA_CACHE_DIR` | 媒体缓存目录 |
| `NEWS_READER_AGENT_DB_PATH` | 临时研究会话数据库 |
| `NEWS_READER_AGENT_RUNTIME_DIR` | Agent 临时运行目录，默认按项目隔离 |
| `NEWS_READER_PI_AGENT_DIR` | Pi 配置来源；默认继承本机 Pi 配置 |
| `NEWS_READER_CODEX` | Codex CLI 可执行文件 |

环境变量名称和数据格式均保留兼容。项目及版本管理独立；数据可继续使用原库，也可以使用原库的副本。设置中会显示当前生效的数据库路径。详见 [原数据接入说明](docs/data-compatibility.md)。

## 新闻研究 Agent

设置中可选择 Pi 或 Codex，分别保存模型、provider、推理强度及连接选项。Codex 获取过的模型目录和推理档位会缓存到本地，刷新页面或重启后可继续选择；“刷新模型目录”用于更新候选，失败时保留上次成功结果。设置中的 DeepSeek 密钥以掩码显示，可更新或删除，并可获取和测试翻译模型。新会话及尚未对话的空会话使用当前保存的配置；已有对话保留首次发送时的配置。支持流式状态、停止、重试、新会话及归档到想法。连接测试使用当前草稿配置。

输入框默认两行，随输入与粘贴增高；桌面最高约八行、手机约五行，并受可见视口限制，超出后在框内滚动。桌面 Enter 发送、Shift + Enter 换行；手机 Enter 换行，点击发送按钮或 Ctrl／Cmd + Enter 发送。切换新闻与发送失败会保留包含换行的草稿。输入框关闭历史提问自动补全，发送后立即清空已发问题。准备会话、提交请求和生成回复期间均可继续编辑下一条草稿，当前任务结束后再发送；返回结果不会清空新草稿，提交失败时仅恢复尚未被新编辑替代的问题。

新闻有标题和链接时，即使全文未抓取、排队中或抓取失败，也可在 Agent 面板输入问题。面板显示“引用新闻标题”与“尚未提供全文”；模型只收到该新闻的标题资料，不会自动发送问题或触发正文抓取。全文后来就绪时，已有对话保留原资料与模型，可新建会话读取全文；尚无消息的空会话会在首次发送前采用当前资料。标题聊天沿用临时会话保存期限、检索能力及回复通知。

独立想法的 Markdown 语法速查在标题、正文或速查区获得焦点时显示，离开后隐藏；示例仍可点击复制，展开／收起偏好会保留。

Pi 使用 OAR/Pi SDK 或兼容 CLI 路径。Codex 使用本机 CLI；应用不复制账号凭据，显式设置 `read-only` 文件沙盒和 `approval_policy=never`。新闻研究任务显式启用 Codex 实时网页搜索（`web_search="live"`）；Pi 沿用本机工具、扩展和 MCP。研究背景、原因、影响、比较及不确定事实时主动检索，纯翻译／摘要和明确只看原文的请求可直接回答。联网失败或工具不可用须说明未完成外部核查，外部事实提供来源链接及检索时间。实际联网能力仍取决于 provider、网络与本机工具配置。未配置 CLI 或凭据不影响基础阅读。

归档读取完整对话，围绕讨论逐渐聚焦的问题提炼最终认识，保留关键依据、适用条件与不确定性，省略被取代的观点、重复铺垫和偏离主题的支线。用户划线引用与问题分字段传输，在面板中显示独立引用块；模型提示词逐行添加 `>` 并单独标注用户问题，历史重放也保留引用。归档时引用随问题一并传入，支持最多 200 条消息、单条 20000 字符，超限明确报错而不截断。归档默认一段、必要时两短段，不加标题或固定栏目，通常 100—250 字、最多 500 字符；以独立想法卡片追加，不改变原对话。

Agent 会话默认保留 72 小时，可在设置中改为 24 小时；运行中的任务不被 TTL 清理。应用仅保存自身会话映射，不删除本机 Codex 全局历史。连接失败会显示实际错误，不使用演示成功结果。

顶栏上游报错入口会展开非模态下拉，可切换日期、按时间或来源分类、筛选并复制日志；日期可直接输入 YYYY-MM-DD 或使用主题日历，支持月份切换、方向键和 Enter 选择，只能选到今天。非法日期会就地提示，保留当前记录。Escape 先关闭日历，再关闭报错下拉；外点关闭，和 Agent 通知同时只显示一个。设置中的更新检查以独立结果区显示结论，说明与检查时间分开呈现。

设置中的「API 管理」统一管理 DeepSeek 与 Jev 的密钥、模型选择和连接测试。DeepSeek 继续用于单篇精读与翻译；Jev 使用 [TypeSafe 原生接口](https://docs.typesafe.ai/api/system-one)，默认 `jev-latest`，用于新闻标题分类，并支持模型目录与独立判断请求测试。两项服务分别保存配置，切换时保留草稿；测试使用已保存的密钥和当前模型选择，无需先保存模型。Jev 模型保存在 `api_models.jev.model`，密钥保存在系统钥匙串，或由 `TYPESAFE_API_KEY` 环境变量提供（环境变量优先），不会写入设置 JSON。

全部已读、Agent 新建／清空、删除 API 密钥、更新重启、放弃设置刷新及删除独立想法使用统一主题确认框，默认聚焦“取消”。确认过程中目标或范围变化时会提示重新操作。浏览器离页保护与系统选库窗口仍保留。

### Agent 回复通知

顶栏右侧的铃铛会提示待查看的 Agent 回复；收起面板、切换新闻、刷新或重开应用后仍可查看。点击铃铛，在下拉框中选择通知，即可回到对应新闻、展开原会话并定位该轮回复；即使新闻不在当前筛选或已加载列表中也可跳转。同一会话的多轮待看消息合并显示。

只有窗口在前台、对应会话展开且该回复实际出现在可见区域时，才清除对应通知。仅打开通知列表、停在旧消息处或跳转失败都会保留通知；“全部标为已读”只处理点击时列出的消息，新到回复保留。清除通知不会改变新闻的已读、收藏或重要状态。通知在前台约每5秒更新，切回窗口时立即刷新，后台暂停轮询。

本轮失败或服务重启中断会显示“本轮未完成”；主动停止不通知，升级前已经完成的历史任务不补发。通知不延长会话原有保存期限；新闻不可访问或会话过期／被删除时，会说明原因并保留通知，可手动“忽略”。不同新闻库的新增会话、任务和通知分别保存归属，即使共用 Agent 库也不会混用。升级前尚无库归属的旧会话仅按新闻ID及URL兼容读取，实际继续提问时才关联当前库，历史任务不补归属或通知。

## 积压新闻总结

左侧「新闻总结」进入历史报告工作台；新闻流中栏顶部栏保持原样。点击「总结并全部已读」先预览，再确认启动。预览有效 15 分钟，包含已关闭信源，排除 Bloomberg 视频；日期、条数与输入大小限制只决定纳入报告的材料，成功归档后会标读全部锁定未读，范围外条数会提前明确展示。失败、取消及新到新闻不受本批标读影响。

设置 → 积压新闻总结范围提供最多自然日（默认 20，含起止）与最多未读条数（默认 6000）。保存后用于下一次预览，运行中批次保持原快照。总结使用「模型与 Agent」中的 Pi/Codex 配置，与单篇 DeepSeek 翻译独立。历史报告及引用保存在当前新闻数据库中；执行进度可在刷新页面后恢复查看。

## 新闻分类

新闻流提供「全部、中国、AI、政治与国际、经济与金融、商业、科技与科学、其他」八个筛选项；每篇新闻保存一个分类。「商业」对应规则中的「商业与产业」。「全部」包含待分类和失败新闻，「其他」只包含已判定为其他主题的新闻。

分类沿用第二轮标题评估规则（`classification/rules.json`）：先判断主要主题；只有 AI 模型、应用、研究、产品或算力本身的技术能力进展归 AI。交易行情归经济与金融，监管及国际依赖归政治与国际，企业经营归商业。非 AI 新闻再判断中国是否为核心事件的直接主体或主要对象；单纯被引用或被呼吁不构成中国主体。模型概率与复核标记供排查使用，不代表准确率。

配置 Jev 后，通过 `python3 app.py` 或项目启动器启动应用，后台自动处理历史队列；刷新索引只排队新标题、修改后的标题或旧规则记录，已完成分类会复用。默认使用 API 管理中保存的 Jev 模型（未设置时 `jev-latest`）；需要固定评估模型时选择 `jev-1.14.0`。分类表独立保存，不改写原始新闻文件及阅读／收藏状态。未配置密钥时队列等待；临时失败最多尝试 4 次，失败后在分类提示处重试；凭据或模型错误暂停调用，修复设置后重试。分类提示中的刷新不会重新请求已完成的分类。

筛选先于服务端分页并覆盖搜索、当前计数与全部已读；侧栏总数仍为全局范围。历史初始化可能耗时并产生 Jev 调用费用，补标期间可继续阅读。

## 版本与更新

版本统一为 `v0.2.1`；npm 包版本为 `0.2.1`。更新源明确配置为本项目的 `https://github.com/xusz12/NewsReader2.git`，不会自动读取其他远程仓库。

在设置 → 系统状态与版本升级中点击「检查更新」，会重新读取 GitHub 的稳定版本 tag（`vN.N.N` 或 `vN.N.N.N`，不含预发布后缀），显示目标版本、检查时间和本地更新条件。没有稳定版本、已是最新版和本地版本领先会分别提示。GitHub 连接或访问限制导致检查失败时可稍后重试。

使用 `启动NewsReader.command` 或 `python3 updater.py --serve` 启动，并保持项目位于干净分支，才能确认更新。未保存的设置需要先保存或重置；未提交的源码或未忽略文件需要先妥善处理。ZIP 下载、detached HEAD 和本地分叉需在终端处理，应用不会自动丢弃修改。

确认后，更新器校验标签提交、目标版本号和更新源，执行快进更新、重启和健康检查；失败时尝试恢复旧提交并重启。数据库、配置、缓存与生成素材已忽略，不阻碍正常更新；目标版本与本地忽略文件同名时会拒绝覆盖。界面显示中文进度，刷新或重新打开设置可恢复查看，完成后点击「刷新使用新版本」。依赖版本发生变化时，仍需按安装说明准备运行依赖；更新器不自动安装依赖。

本地生成的 `output/`、日志、覆盖率报告、编辑器配置和 `.env` 等不纳入 Git，正式应用资源、锁文件、测试与文档继续纳入版本管理。发布新版本时需保证版本元数据一致，并推送对应稳定 tag；仅修改本地版本号不会产生远端更新。
