# 本机 ReutersBrowser news 列表适配器

保持命令、返回列 `rank/title/time/url`、Asia/Shanghai 时间格式及 limit 的原有默认值和范围限制。
显式设置 `navigateBefore: false`，由适配器自己打开一次 Reuters 首页，为同源列表 API 准备浏览器环境。

## 恢复边界

- 导航、页面状态检查、接口请求和退避共用 **30 秒**总期限。
- 短暂导航错误最多尝试 2 次，间隔 1 秒；状态检查的短暂浏览器错误最多重试 2 次。
- 页面状态每秒检查一次。自动验证或加载期间不刷新网页、不调用列表接口。
- 列表接口总共最多 **3 次**尝试；两次重试分别至少等待 **2 秒、5 秒**，从前一次失败处理完成后计时。
- `Retry-After` 支持秒数与 HTTP 日期，取它和本地退避中的较大值。超过剩余预算时到期退出，不提前请求。
- HTTP 401/403 即使没有验证 iframe 也允许有限重试。失败后重新检查页面，识别请求触发的新验证。
- 交互验证码、明确访问封锁或登录订阅要求直接返回 `AUTH_REQUIRED`。
- 临时网络错误、408/429、部分 5xx、空结果和可识别的验证 HTML 允许有限重试；404、普通格式错误直接返回结构化错误。
- 单次 fetch 最多 8 秒（剩余预算更少时相应缩短），使用 AbortController，响应体读取也在期限内。
- fetch 使用 `page.evaluateOnce`，避免 opencli 核心在页面跳转后自动重放请求。只读状态检查使用 `page.evaluate`。

所有等待运行在 Node 中，浏览器只执行短小的状态检查或单次 fetch。
外层期限到达后不会再发起操作；已经发送的浏览器桥接调用无法由本适配器取消。
不修改网站验证逻辑，也不自动操作验证码。

```sh
npx --yes vitest@5.0.4 run --root "$HOME/.opencli/clis" reuters-section/news-recovery.test.js --cache=false
```
